### 1.2 三套规则库并存（⚠️ 核心架构问题）

```
┌──────────────────┐  ┌─────────────────────┐  ┌──────────────────┐
│ rules.json       │  │ config/rules/*.json   │  │ compliance_rules │
│ 264条           │  │ 6088条                │  │ .json 30条       │
│ 被 RuleChecker   │  │ 无引擎加载            │  │ 被 ComplianceRule│
│ 加载并执行       │  │ ⚠️ 死数据              │  │ Engine 加载      │
│ Schema: 顶层数组  │  │ Schema: 顶层数组       │  │ Schema: 嵌套结构  │
└──────────────────┘  └─────────────────────┘  └──────────────────┘
```

**规则加载链路**：
```
step5_engineering.py → RuleChecker(config/rules.json)
                        → _load_rules() → 只读 rules.json 中的 rules 数组
                        → _rule_applies_to_project() → building_type 过滤
                        → _collect_texts() → 读 output/*_unified.json
                        → _filter_texts_by_discipline() → 按专业过滤文本
                        → _check_single_rule() → 逐规则遍历所有文本
                           → _determine_single_text_status()
                              → _match_keywords() + _match_regex()
                              → _check_context_indicators()
```

## 二、修改约束法则

### 2.1 文件修改安全区（可自由修改）

| 文件 | 职责 | 允许操作 |
|------|------|---------|
| `config/rules.json` | 主规则库 | 增删改规则、优化keywords/regex/exclude_keywords |
| `output/project_params.json` | 项目元信息 | 填充真实项目名称/地址/单位 |
| `report/report_polisher.py` | 报告格式化 | 修改表格结构、输出格式 |
| `scripts/*.py` | 一次性工具脚本 | 自由修改 |
| `docs/*.md` | 文档 | 自由修改 |

### 2.2 文件修改谨慎区（需理解上下文）

| 文件 | 关键函数 | 修改前必读 |
|------|---------|-----------|
| `engine/rule_checker.py` | `_check_single_rule()` L260-380 | NEGATIVE_INDICATORS在第9-13行，_filter_texts_by_discipline在L140-175 |
| `engine/rule_checker.py` | `_determine_single_text_status()` L204-228 | _extract_context_with_numbers() 在 L204-216 |
| `src/step5_engineering.py` | `main()` | 依赖链：JsonLoader→RuleChecker→ElevationCalc→MepCoordinator→CrossDiscipline→EngineeringAnalyzer |

### 2.3 规则文件修改规范

修改 `rules.json` 中一条规则时，必须确保：
```json
{
  "rule_id": "rule_XXX",          // 必须唯一，与现有ID不冲突
  "name": "...",                  // 中文描述
  "discipline": "建筑/结构/给排水/暖通/电气/消防",
  "keywords": ["...", "..."],     // check_type="any"时匹配任一，"all"时全部匹配
  "check_type": "any",            // any | all
  "description": "...",
  "is_mandatory": true/false,     // true=强条, false=强标
  "code_reference": "GB XXXX-XXXX 第X.X.X条",
  "regex": "...",                 // 可选，精确匹配数值
  "applicable_building_types": ["大学", "住宅", ...],  // 必须填写，空数组=通用
  "exclude_keywords": ["满足要求", ...]  // 可选，匹配到这些词则跳过
}
```

### 2.4 不可触碰的约束

| 规则 | 原因 |
|------|------|
| 不修改 `config/rules/*.json` 只修改 `rules.json` | 前者是死数据，改了也无效 |
| 不修改 `engine/compliance_rule_engine.py` 的加载路径 | 它与RuleChecker独立，混乱会导致双重计数 |
| 不删除 `output/*_unified.json` | 这是step1的输出，全流程依赖它 |
| `project_params.json` 的 `building_type` 只能从枚举中选 | 见 `config/building_classification.py` 的 `BUILDING_TYPES` |
| 修改polisher后必须重跑完整流程验证 | 它消费step5输出，中间缓存不可靠 |
