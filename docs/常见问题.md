# 施工图智能审查系统 v6.0 - 常见问题

## 1. 安装与环境

### Q1.1: 安装 ezdxf 失败怎么办？

**现象**: `pip install ezdxf` 报错。

**解决方案**:

Windows:
```bash
# 使用预编译 wheel 包
pip install --only-binary=ezdxf ezdxf
```

Linux:
```bash
# 安装系统编译依赖后重试
sudo apt update
sudo apt install build-essential python3-dev
pip install ezdxf
```

### Q1.2: Python 版本要求？

**要求**: Python 3.11 及以上。

**验证方法**:
```bash
python --version
```

如果低于 3.11，请从 https://www.python.org/downloads/ 下载安装最新版本。

### Q1.3: 系统是否支持 Windows 7？

不支持。最低要求 Windows 10 或 Windows Server 2016+。

### Q1.4: 是否需要 GPU？

不需要。系统基于文本匹配、规则引擎和LLM API调用，无需 GPU 加速。但需要网络连接，因为 LLM 功能（智谱 glm-4-flash）通过 API 调用实现。

### Q1.5: 是否需要网络连接？

需要。系统默认启用 LLM 功能（智谱 glm-4-flash），通过 API 调用实现智能判定、RAG审核等功能。如果仅使用规则引擎审查（不启用LLM），则无需网络。

## 2. 运行与使用

### Q2.1: 运行时提示 "master.py: 没有那个文件或目录"

**原因**: 当前工作目录不在项目根目录。

**解决**: 先 `cd` 到项目根目录，再执行命令。

```bash
cd f:\AI智能审图系统_v6.0_项目开发
python src/master.py
```

### Q2.2: 提示 "未找到任何 .dxf 文件"

**原因**:
1. `--dxf-dir` 参数指向的目录不存在
2. 目录下没有 `.dxf` 文件
3. 文件名后缀大小写不正确

**解决**:
```bash
# 确认目录存在
dir ./input

# 确认有 .dxf 文件（不区分大小写）
dir ./input/*.dxf

# 指定正确路径
python src/master.py --dxf-dir ./input
```

### Q2.3: 提示 "未找到任何 *_unified.json 文件"

**原因**: Step 1 未执行，或 `--json-dir` 参数指向的目录为空。

**解决**:
```bash
# 先执行 Step 1
python src/step1_extract.py --dxf-dir ./input --output-dir ./json_data

# 再执行后续步骤
python src/master.py --skip-step 1
```

### Q2.4: 输出目录下没有报告文件

**原因**: 只执行了前几个步骤，未执行 Step 5。

**解决**: 确保执行完整工作流或指定执行 Step 5：
```bash
python src/master.py
# 或
python src/step5_engineering.py --json-dir ./json_data --output-dir ./output
```

### Q2.5: 如何只查看规则检查结果，不执行全部步骤？

```bash
python src/master.py --only-step 2
```

结果保存在 `./output/step2_compliance_result.json`。

### Q2.6: 如何配置 LLM API Key？

**方法一**：通过环境变量设置（推荐）

```bash
# Windows
set ZHIPU_API_KEY=your_api_key_here

# Linux/Mac
export ZHIPU_API_KEY=your_api_key_here
```

**方法二**：在 `config/project_config.json` 中配置 `llm.api_key_env` 指向环境变量名称。

**注意**：禁止将 API Key 硬编码在代码或配置文件中。

### Q2.7: LLM 调用失败怎么办？

**常见原因与解决**：

1. **网络不通**：检查网络连接，确保能访问 `open.bigmodel.cn`
2. **API Key 未配置**：确认 `ZHIPU_API_KEY` 环境变量已设置
3. **API Key 无效**：登录智谱开放平台检查 Key 状态和余额
4. **接入点故障**：系统配置6个接入点，会自动故障转移，6个均失败时请稍后重试

### Q2.8: LLM 调用会产生多少费用？

系统默认使用智谱 glm-4-flash 模型，该模型为低成本模型，单次审查费用极低。费用主要取决于：
- 审查的图纸数量
- 规则命中数量（LLM判定仅对命中规则触发）
- RAG审核的深度

如需控制费用，可通过 `--disable-llm` 参数关闭LLM功能，仅使用规则引擎审查。

## 3. 输入与数据

### Q3.1: 支持哪些 DXF 版本？

支持 ezdxf 库支持的所有 DXF 版本，推荐使用 DXF 2010 (AC1027) 及以上版本。

### Q3.2: DXF 文件名有什么要求？

建议文件名包含专业关键词以获得准确的自动分类：

- **包含关键词**：如 `建筑-一层平面图.dxf`、`结构-梁配筋图.dxf`
- **避免纯 UUID 命名**：如 `a1b2c3d4-e5f6-7890.dxf`（可处理但降低可读性）

系统采用两级策略进行专业识别：第一级基于文件名关键词匹配，第二级基于图纸内容特征深度识别，未识别率仅2.7%。

### Q3.3: 一个DXF文件包含多个专业的图纸怎么办？

系统采用两级策略进行专业识别，即使文件名不含明确关键词，第二级深度识别也能根据图纸内容特征进行分类。建议仍尽量分拆为多个 DXF 文件，每个文件对应一个专业，以获得最佳审查效果。

### Q3.4: 输入数据必须是 DXF 格式吗？

不是。Step 1 是 DXF→JSON 的提取步骤。如果已有符合格式的 `*_unified.json` 文件，可以跳过 Step 1：
```bash
python src/master.py --skip-step 1
```

### Q3.5: 如何指定建筑类型？

通过 `--building-type` 参数指定建筑类型，系统会自动过滤适用规则：

```bash
# 公建项目
python src/master.py --dxf-dir ./input --output-dir ./output --building-type 公建

# 住宅项目
python src/master.py --dxf-dir ./input --output-dir ./output --building-type 住宅
```

未指定时默认加载全部规则（280条），包括公建专用和住宅专属规则。

## 4. 结果与报告

### Q4.1: 报告中的 "不适用" 是什么意思？

表示当前审查数据中没有匹配到该规则的适用场景（关键词未命中）。例如，当审查数据中没有"卧室"关键词时，关于卧室净高的规则会被标记为"不适用"。

### Q4.2: 报告中的 "待核实" 是什么意思？

表示规则关键词命中但正则匹配不充分，或证据链等级为 L0/L1，需要人工进一步核实。

### Q4.3: 为什么有些规则检查结果是 "不合规" 但实际设计是合理的？

系统基于文本匹配、正则表达式和LLM语义理解进行审查，可能存在以下误报：
1. 文本表述方式与规则正则不匹配
2. 图纸中的说明文字与设计实际不一致
3. 特殊设计超出了规则的常规判断范围

建议：对"不合规"结果进行人工复核确认。Step 8（二次审查）会自动消除部分误报。

### Q4.4: 报告是详细的还是摘要格式？

系统生成6份详细报告：
1. **强条合规性审查报告** - 280条规则逐条审查结果
2. **基础错漏排查报告** - 标高、碰撞、管综分析
3. **跨专业一致性校验报告** - 专业间一致性检查
4. **综合评估摘要** - 全局风险概览
5. **图纸会审问题清单** - 按四级风险分级（严重/重要/一般/提示）分类
6. **LLM分析报告** - LLM智能判定详情

所有报告均为 Markdown 格式，包含匹配文本、证据引用、规范条文编号。

### Q4.5: 能否生成 PDF 格式报告？

当前版本输出 Markdown 格式。可以通过以下方式转换：
- 使用 Typora、VS Code 等工具将 Markdown 导出为 PDF
- 使用 pandoc 命令行转换：
  ```bash
  pip install pandoc
  pandoc 报告.md -o 报告.pdf
  ```

### Q4.6: 报告中 "严重" 和 "重要" 风险等级有什么区别？

系统采用四级风险分级：

| 等级 | 含义 | 处理要求 |
|------|------|----------|
| **严重** | 违反强制性条文，存在安全隐患 | 必须修改，不得通过审查 |
| **重要** | 违反重要规范要求，影响使用功能 | 应当修改，需设计单位回复 |
| **一般** | 不满足一般性规范要求 | 建议修改，可协商处理 |
| **提示** | 潜在问题或优化建议 | 供参考，酌情处理 |

"严重"级别问题通常对应国家强制性条文（如防火间距、疏散宽度等），不允许任何妥协；"重要"级别问题对应影响建筑功能和安全的重要规范，需要设计单位给出合理解释或修改方案。

## 5. 性能与限制

### Q5.1: 审查一批DXF文件需要多久？

| 步骤 | 处理时间 |
|------|----------|
| Step 0 锚点提取 | 1-2秒/文件 |
| Step 1 DXF提取 | 1-3秒/文件 |
| Step 2 合规审查 | 2-5秒/文件（含LLM判定时视网络情况） |
| Step 3 错漏排查 | 1-3秒/文件 |
| Step 4 跨专业校验 | 1-2秒/文件 |
| Step 5 报告生成 | 1-2秒/文件 |
| Step 6 BIM管线 | 2-5秒/文件 |
| Step 7 RAG审核 | 3-8秒/文件（含LLM调用） |
| Step 8 二次审查 | 1-2秒/文件 |

**批量处理参考**：112个文件完整审查约98秒（不含LLM调用），含LLM调用时视网络情况增加。

系统内置 LRU 缓存机制与性能监控，自动优化重复计算与内存使用。

### Q5.2: 支持同时处理多个 DXF 文件吗？

支持。系统会自动扫描 `--dxf-dir` 目录下的所有 `.dxf` 文件并批量处理。

### Q5.3: 最大的 DXF 文件大小限制？

建议单个 DXF 文件不超过 50MB。超大文件可在 `project_config.json` 中调整 `max_file_parse_time` 参数。

### Q5.4: 系统支持多线程并行处理吗？

当前版本为单线程串行处理。如需并行：
1. 将 DXF 文件分组到不同目录
2. 在多个终端中分别执行：
   ```bash
   # 终端1
   python src/step1_extract.py --dxf-dir ./input/group1 --output-dir ./json_data
   # 终端2
   python src/step1_extract.py --dxf-dir ./input/group2 --output-dir ./json_data2
   ```

## 6. 自定义与扩展

### Q6.1: 如何添加新的审查规则？

编辑 `config/rules.json` 的 `rules` 数组，添加新的规则条目：

```json
{
  "rule_id": "rule_281",
  "category": "建筑",
  "description": "新规则描述",
  "keywords": ["关键词1", "关键词2"],
  "regex": "正则匹配表达式",
  "severity": "严重",
  "standard_code": "GB XXXX-XXXX 第X.X.X条",
  "building_type": "公建"
}
```

添加后系统会自动加载，无需重启。`severity` 可选值：`严重`、`重要`、`一般`、`提示`。`building_type` 可选值：`公建`、`住宅`，留空表示通用规则。

### Q6.2: 如何添加新的规范？

编辑 `config/normative_database.json` 的 `normative_codes` 数组：

```json
{
  "code": "GB XXXX-XXXX",
  "name": "规范名称",
  "category": "专业",
  "version": "版本号",
  "effective_date": "YYYY-MM-DD"
}
```

### Q6.3: 能否调整规则严重等级？

可以。直接编辑 `config/rules.json` 中对应规则的 `severity` 字段，可选值：`严重`、`重要`、`一般`、`提示`。

### Q6.4: 规则支持热加载吗？

支持。`RuleChecker.reload_rules()` 方法可以在不重启程序的情况下重新加载规则文件。

### Q6.5: 如何扩展新的分析引擎？

1. 在 `engine/` 目录下创建新的 `.py` 文件
2. 实现核心类，提供 `run_all_checks()` 方法
3. 在对应的 step 脚本中导入并调用
4. 在 `tests/` 目录下添加对应的测试用例

## 7. 建筑类型与碰撞检测

### Q7.1: 建筑类型适配如何工作？

系统根据 `--building-type` 参数自动过滤规则：

- **公建**：启用公建专用规则（如公共建筑防火、疏散等），过滤住宅专属规则（如住宅净高、卧室面积等）
- **住宅**：启用住宅专属规则，过滤公建专用规则
- **未指定**：加载全部280条规则，审查结果中不适用规则会标记为"不适用"

### Q7.2: 碰撞检测为什么从2145个降到14个？

早期版本采用全局两两碰撞检测，即所有图纸中的构件两两比对，产生大量虚假碰撞（如不同楼层、不同区域的构件被误判为碰撞）。

v6.0 改进为：
1. **按文件分组**：仅在同一区域/楼层的图纸间进行碰撞检测
2. **收紧阈值**：提高碰撞判定的精度要求，过滤掉距离过远的"碰撞"

效果：从2145个虚假碰撞降至14个真实碰撞，准确率大幅提升。

### Q7.3: 专业识别未识别率2.7%意味着什么？

系统采用两级策略进行专业识别：
- 第一级：基于文件名关键词匹配，快速分类
- 第二级：对第一级未识别的文件，基于图纸内容特征进行深度识别

2.7%的未识别率意味着约100个文件中有2-3个无法自动归类，这些文件会被标记为"未识别"，需人工确认专业归属。

## 8. 错误与故障

### Q8.1: "module 'ezdxf' has no attribute 'readfile'"

**原因**: ezdxf 未正确安装或版本不兼容。

**解决**:
```bash
pip uninstall ezdxf
pip install ezdxf
python -c "import ezdxf; print(ezdxf.__version__)"
```

### Q8.2: 执行 DXF 提取时出现乱码

**原因**: DXF 文件编码与系统默认编码不一致。

**解决**:
```bash
# Windows: 设置 UTF-8 环境变量
set PYTHONUTF8=1
python src/step1_extract.py
```

### Q8.3: 测试执行失败

```bash
# 确保在项目根目录执行
cd f:\AI智能审图系统_v6.0_项目开发

# 查看详细错误信息
pytest tests/ -v --tb=long
```

### Q8.4: 报告中的中文显示为乱码

**原因**: 终端编码不支持中文。

**解决**:
```bash
# Windows PowerShell
chcp 65001

# 或 VS Code 终端中运行
```

### Q8.5: LLM 调用超时

**原因**: 网络延迟或API服务端响应慢。

**解决**:
1. 检查网络连接是否正常
2. 在 `config/project_config.json` 中增大 `llm.timeout` 值（默认30秒）
3. 系统会自动重试（默认3次），6个接入点自动故障转移
4. 如持续超时，可使用 `--disable-llm` 临时关闭LLM功能

### Q8.6: LLM 返回空结果或异常内容

**原因**: API Key无效、余额不足或模型服务异常。

**解决**:
1. 登录智谱开放平台检查API Key状态和余额
2. 确认 `ZHIPU_API_KEY` 环境变量值正确
3. 查看日志 `./output/logs/system.log` 中的LLM调用详情
