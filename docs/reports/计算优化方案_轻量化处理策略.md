# 计算优化方案 — 轻量化处理策略

## 一、当前计算瓶颈分析

### 1.1 实际计算量

```
规则库规模：
├── 强制性规则：262条
├── 跨专业检查：22项
└── 总计：284个检查项

计算量估算（50个DXF文件，每文件1000行）：
├── 规则检查：262条 × 50文件 × 1000行 = 13,100,000 次字符串匹配
├── 跨专业检查：22项 × 多文件交叉比对 ≈ 1,000,000 次操作
├── 标高计算：正则提取 + 数值计算 ≈ 500,000 次操作
├── 碰撞检测：文本标高比对 ≈ 500,000 次操作
└── 单次运行总计：约15M次字符串/数值操作

问题：
├── 13M次字符串匹配 → CPU密集型
├── 全量顺序执行 → 无法并行
├── 所有规则对所有文件 → 大量无效检查
└── 跨专业检查N×M复杂度 → 文件越多越慢
```

### 1.2 瓶颈识别

| 瓶颈点 | 原因 | 影响 |
|--------|------|------|
| **规则全量扫描** | 262条规则对50个文件全扫描 | 13M次匹配，90%可能无关 |
| **跨专业N×M比对** | 建筑vs结构vs机电...两两比对 | 复杂度O(N²)，文件越多越慢 |
| **顺序执行** | Step1→Step2→Step3...串行 | 无法利用多核CPU |
| **重复加载** | 每个Step重新加载JSON文件 | I/O开销大 |
| **无缓存机制** | 每次运行从零开始 | 无法复用中间结果 |

---

## 二、优化策略：分层减负

### 2.1 核心思想

```
不是所有规则都要检查所有文件。
不是所有文件都要立即处理。
不是所有步骤都要顺序执行。
```

### 2.2 三层减负策略

```
┌─────────────────────────────────────────────────────────────┐
│ Layer 1: 预筛选（减少规则数）                                 │
│ 策略：按专业/建筑类型/阶段，只加载相关规则                    │
│ 效果：262条 → 约50条（减少80%）                              │
└─────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────┐
│ Layer 2: 文件分组（减少文件数）                               │
│ 策略：按楼栋-楼层-专业分组，分组并行处理                      │
│ 效果：50文件 → 10组并行（减少串行等待）                       │
└─────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────┐
│ Layer 3: 增量计算（减少重复计算）                             │
│ 策略：缓存中间结果，只计算变更部分                            │
│ 效果：第二次运行时间减少90%                                   │
└─────────────────────────────────────────────────────────────┘
```

## 三、具体优化方案

### 3.1 Layer 1: 规则预筛选（减少80%规则检查）

**当前做法：**
```python
# 262条规则全部加载，对所有文件检查
for rule in all_262_rules:  # 262次循环
    for file in all_files:   # 50次循环
        for line in file:    # 1000次循环
            check(rule, line)  # 13,100,000次检查
```

**优化做法：**
```python
# Step 1: 识别项目特征
project_features = {
    'building_type': '住宅',  # 从project_config或图纸识别
    'disciplines': ['建筑', '结构', '电气', '给排水'],  # 实际有的专业
    'phases': ['设计阶段']  # 当前阶段
}

# Step 2: 按特征过滤规则
filtered_rules = filter_rules(all_rules, project_features)
# 住宅项目：只加载住宅相关规则（约30条）
# 有电气的项目：只加载电气规则（43条）
# 结果：从262条减少到约50条

# Step 3: 只检查相关规则
for rule in filtered_rules:  # 50次循环（减少80%）
    for file in relevant_files:  # 只检查相关专业文件
        check(rule, file)
```

**实现代码：**
```python
class RuleFilter:
    """规则预筛选器"""
    
    def filter_by_building_type(self, rules, building_type):
        """按建筑类型过滤"""
        return [r for r in rules if 
                r.get('applicable_types', ['all']) in ['all', building_type]]
    
    def filter_by_discipline(self, rules, available_disciplines):
        """按可用专业过滤"""
        return [r for r in rules if 
                r.get('discipline') in available_disciplines]
    
    def filter_by_phase(self, rules, current_phase):
        """按当前阶段过滤"""
        # 设计阶段只检查设计相关规则
        # 施工阶段检查施工相关规则
        phase_map = {
            'design': ['设计', '通用'],
            'construction': ['施工', '验收', '通用'],
            'acceptance': ['验收', '通用']
        }
        applicable_categories = phase_map.get(current_phase, ['通用'])
        return [r for r in rules if 
                r.get('category', '通用') in applicable_categories]
```

**效果：**
- 住宅项目：262条 → 约50条（减少80%）
- 仅机电审查：262条 → 约150条（减少40%）
- 计算时间：从5分钟 → 1分钟

### 3.2 Layer 2: 文件分组并行（减少串行等待）

**当前做法：**
```python
# 顺序处理所有文件
for file in all_files:  # 50个文件顺序处理
    process(file)  # 总时间 = 50 × 单个文件时间
```

**优化做法：**
```python
from concurrent.futures import ProcessPoolExecutor
import multiprocessing

# Step 1: 按楼栋-楼层-专业分组
groups = group_files_by_spatial(all_files)
# 结果：
# {
#   '1号楼': {
#     'B1': {'建筑': [file1], '结构': [file2], ...},
#     '1F': {'建筑': [file3], '电气': [file4], ...},
#     ...
#   },
#   '2号楼': {...}
# }

# Step 2: 组内并行处理
with ProcessPoolExecutor(max_workers=multiprocessing.cpu_count()) as executor:
    futures = []
    for building, floors in groups.items():
        for floor, disciplines in floors.items():
            # 每个楼层组作为一个任务
            future = executor.submit(process_floor_group, building, floor, disciplines)
            futures.append(future)
    
    # 等待所有组完成
    results = [f.result() for f in futures]

# Step 3: 合并结果
merged_result = merge_results(results)
```

**实现代码：**
```python
class ParallelProcessor:
    """并行处理器"""
    
    def __init__(self, max_workers=None):
        self.max_workers = max_workers or multiprocessing.cpu_count()
    
    def process_in_parallel(self, file_groups, process_func):
        """
        按组并行处理
        
        Args:
            file_groups: {'1号楼-B1': [files], '1号楼-1F': [files], ...}
            process_func: 处理函数
        """
        with ProcessPoolExecutor(max_workers=self.max_workers) as executor:
            # 提交所有任务
            future_to_group = {
                executor.submit(process_func, group_name, files): group_name
                for group_name, files in file_groups.items()
            }
            
            # 收集结果
            results = {}
            for future in as_completed(future_to_group):
                group_name = future_to_group[future]
                try:
                    results[group_name] = future.result()
                except Exception as e:
                    logger.error(f"处理组 {group_name} 失败: {e}")
                    results[group_name] = None
            
            return results
```

**效果：**
- 8核CPU：理论加速8倍
- 实际加速：4-6倍（考虑I/O开销）
- 50个文件：从5分钟 → 1分钟

### 3.3 Layer 3: 增量计算（减少90%重复计算）

**当前做法：**
```python
# 每次运行从零开始
每次运行 = DXF提取 + 规则检查 + 碰撞检测 + ...
# 时间：5分钟（每次都一样）
```

**优化做法：**
```python
# 第一次：全量计算
if not cache_exists():
    result = full_process()
    cache.save(result)

# 第二次及以后：只计算变更
else:
    # 1. 检查哪些文件变更
    changed_files = detect_changes()
    
    # 2. 加载缓存结果
    cached_result = cache.load()
    
    # 3. 只重新处理变更文件
    for file in changed_files:
        update_result = process_file(file)
        cached_result.update(file, update_result)
    
    # 4. 保存更新结果
    cache.save(cached_result)
    
    # 时间：5分钟 → 30秒（只处理变更文件）
```

**实现代码：**
```python
class IncrementalCache:
    """增量计算缓存"""
    
    def __init__(self, cache_dir='./cache'):
        self.cache_dir = cache_dir
        self.file_hashes = {}  # 文件哈希值
        self.result_cache = {}  # 结果缓存
    
    def get_file_hash(self, filepath):
        """计算文件哈希"""
        import hashlib
        with open(filepath, 'rb') as f:
            return hashlib.md5(f.read()).hexdigest()
    
    def detect_changes(self, files):
        """检测变更文件"""
        changed = []
        for file in files:
            current_hash = self.get_file_hash(file)
            cached_hash = self.file_hashes.get(file)
            if current_hash != cached_hash:
                changed.append(file)
                self.file_hashes[file] = current_hash
        return changed
    
    def get_cached_result(self, file):
        """获取缓存结果"""
        return self.result_cache.get(file)
    
    def save_result(self, file, result):
        """保存结果到缓存"""
        self.result_cache[file] = result
        # 持久化到磁盘
        self._persist()
```

**效果：**
- 第一次运行：5分钟（全量）
- 第二次运行：30秒（只处理变更，减少90%）
- 适用于：设计迭代、局部修改场景

## 四、轻量级任务拆分方案

### 4.1 最小可执行任务单元

```
将大任务拆分为可独立执行的小任务：

原任务：审查50个DXF文件（5分钟）

拆分后：
├── Task 1: 提取1号楼B1层（30秒）
├── Task 2: 提取1号楼1F层（30秒）
├── Task 3: 提取1号楼2F层（30秒）
├── Task 4: 提取2号楼B1层（30秒）
├── Task 5: 提取2号楼1F层（30秒）
└── ...（共10个任务，每个30秒）

优势：
├── 单个任务失败不影响其他
├── 可并行执行（10个任务同时跑）
├── 可增量执行（只跑变更的任务）
└── 可分布式执行（多台机器分担）
```

### 4.2 任务优先级队列

```python
from queue import PriorityQueue

class PrioritizedTaskQueue:
    """优先级任务队列"""
    
    def __init__(self):
        self.queue = PriorityQueue()
        self.priority_map = {
            'critical_path': 1,    # 关键路径上的文件优先
            'design_phase': 2,     # 设计阶段问题优先
            'severe_issue': 3,     # 有严重问题的文件优先
            'normal': 4            # 普通文件
        }
    
    def add_task(self, task, priority='normal'):
        """添加任务"""
        priority_value = self.priority_map.get(priority, 4)
        self.queue.put((priority_value, task))
    
    def process_queue(self, worker_func):
        """按优先级处理任务"""
        while not self.queue.empty():
            priority, task = self.queue.get()
            worker_func(task)
```

### 4.3 流式处理（边提取边检查）

```python
# 当前：先全部提取，再全部检查
files = extract_all_dxf()  # 2分钟
results = check_all(files)  # 3分钟
# 总时间：5分钟

# 优化：边提取边检查（流水线）
def streaming_process():
    extract_queue = Queue()
    check_queue = Queue()
    
    # 提取线程
    def extractor():
        for dxf_file in dxf_files:
            json_file = extract_dxf(dxf_file)
            extract_queue.put(json_file)
    
    # 检查线程
    def checker():
        while True:
            json_file = extract_queue.get()
            if json_file is None:
                break
            result = check_file(json_file)
            check_queue.put(result)
    
    # 启动流水线
    Thread(target=extractor).start()
    Thread(target=checker).start()
    
    # 收集结果
    results = []
    for _ in range(len(dxf_files)):
        results.append(check_queue.get())
    
    return results
# 总时间：max(2,3) = 3分钟（减少40%）
```

## 七、总结

### 核心问题

计算量太大是因为：
1. 262条规则全扫描 → **80%是无关检查**
2. 50个文件顺序执行 → **无法利用多核**
3. 每次从零开始 → **大量重复计算**

### 解决方案

三层减负：
1. **规则预筛选**：262条 → 50条（减少80%）
2. **文件并行**：顺序 → 8核并行（加速6x）
3. **增量计算**：每次都全量 → 只算变更（加速10x）

### 预期效果

```
当前：50个文件，262条规则，顺序执行 = 5分钟
优化：50个文件，50条规则，8核并行，增量计算 = 10秒
加速：30倍
```
