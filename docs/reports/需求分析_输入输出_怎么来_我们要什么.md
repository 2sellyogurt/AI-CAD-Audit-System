# AI智能审图系统 — 需求分析（基于实际代码+行业知识）

## 一、现状：系统实际能做什么

### 1.1 当前v6.0实际能力（基于代码事实）

```
输入：DXF图纸文件
  ↓
tools_extract_dxf.py 用ezdxf库读取DXF，提取TEXT/MTEXT文本实体
  ↓ 清理去重后输出
unified.json = {raw_texts: [文本行], elevations: [标高值], metadata: {专业, 楼栋}}
  ↓
rule_checker.py 对262条规则逐条做关键词搜索（exact/any/regex三种模式）
  判定逻辑：找到证据→合规，找到部分→待核实，没找到→看专业覆盖情况
  ↓
elevation_calc.py 用正则提取梁截面、板厚、面层厚度，计算净高=层高-梁高-面层
  ↓
collision_detect.py 用正则提取桥架规格和标高，做文本级别的碰撞判断
  ↓
cross_discipline.py 跨文件搜索关键词，比对各专业参数值是否一致
  ↓
engineering_analysis.py 搜索弯头/套管/检修口等关键词，硬编码评分
  ↓
report_generator_v50.py 生成3份Markdown报告
meeting_list.py 生成会审问题清单Markdown
```

### 1.2 当前系统的真实局限（基于代码事实）

| 局限 | 代码证据 |
|------|---------|
| **只提取文本，不提取几何** | `tools_extract_dxf.py` 只遍历TEXT/MTEXT，不提取DIMENSION/ATTRIB/LINE/CIRCLE |
| **规则检查=关键词搜索** | `rule_checker.py` 的三种check_type本质都是字符串匹配 |
| **标高type永远是"未知"** | `extract_elevations()` 输出的type字段未做分类 |
| **净高计算不精确** | 取max(梁高,板厚)而非相加，板厚默认120mm硬编码 |
| **碰撞检测是文本匹配** | 比较同文件内标高数值，不是几何空间计算 |
| **工程分析用硬编码单价** | 弯头400元、三通600元写死在代码里 |
| **梁开洞检查是空实现** | `meeting_list.py` 的`_collect_beam_drilling_issues()`只有pass |
| **经验匹配传入None** | `src/master.py` Step1.5 传入`report_texts=None` |
| **报告截断问题** | 碰撞最多30条、梁开洞最多20条、跨专业最多20条 |
| **问题描述截断60字符** | `question[:60]` 丢失信息 |

## 二、行业实际要什么：监理在现场到底查什么

### 2.1 从6份专监文档提取的可操作知识

6份文档共提取出 **280+条具体可检查项**，按类别分布：

| 类别 | 条数 | 示例 |
|------|------|------|
| 材料规格检查 | 43条 | 桥架板厚、风管板厚、PPR管壁厚、配电箱钢板厚度 |
| 电气测试试验 | 35条 | 绝缘电阻≥0.5MΩ、接地电阻≤4Ω、漏电保护器≤30mA |
| 给排水测试 | 25条 | 水压试验、通球试验、闭水试验、坡度检查 |
| 暖通测试 | 20条 | 风管漏风量、风口风量偏差≤±15%、水温偏差 |
| 消防测试 | 25条 | 水泵启动≤55秒、消火栓压力≥0.25MPa、喷头距离 |
| 管线综合 | 40条 | 强弱电间距≥300mm、检修通道≥400mm、净高控制 |
| 防雷接地 | 12条 | 搭接长度、焊接质量、防腐处理 |
| 建筑类型专项 | 35条 | 住宅层高≥3.0m、手术室等电位≤0.1Ω |
| 甲方验收 | 30条 | A签扫码、防火封堵、保温切开检查 |
| 施工工艺 | 15条 | 套管安装、阀门方向、支吊架间距 |

### 2.2 行业知识的本质特征

```
监理在现场查的东西，和当前系统检查的东西，是两个维度：

当前系统检查的：          行业要查的：
"图纸上有没有提到X"       "X的数值是不是≥Y"
"关键词是否出现"          "用工具实测是否达标"
"各专业参数是否一致"      "现场施工是否按图纸做"

差距：
  当前系统 = 图纸文本的存在性检查
  行业需求 = 数值合规性验证 + 施工符合性验证 + 测试达标性验证
```

## 三、需求分析：输入什么、输出什么、怎么来、我们要什么

### 3.1 输入什么

```
当前输入：
  DXF图纸文件 → 提取文本 → unified.json

实际需要的输入（按优先级）：
  ┌─────────────────────────────────────────────────────────────┐
  │ Level 1（已有）：DXF图纸 → 文本提取                          │

  │   └── 专业系统（有哪些机电系统）                             │
  │ Level 3（缺失）：设计条件                                    │
  │   ├── 工作压力（给水/消防/暖通各系统）                      │

  │   └── 系统参数（风量/水量/照度等）                           │

  └─────────────────────────────────────────────────────────────┘
```

### 3.3 怎么来（技术路径）

```
当前做法：
  DXF → 提取文本 → 关键词搜索 → 报告

实际需要的做法：

  ┌─────────────────────────────────────────────────────────────┐
  │ Step 1: 数据提取（增强）                                     │
  │   当前：只提取TEXT/MTEXT                                     │
  │   增强：+DIMENSION尺寸标注 + ATTRIB块属性 + 图层信息         │
  │   效果：能提取到梁截面200x500、桥架300x100等结构化数值       │
  │                                                             │
  │ Step 2: 参数识别（新增）                                     │
  │   当前：无                                                  │
  │   新增：从文本中识别项目参数（高度/层数/耐火等级/抗震烈度）  │
  │   方法：正则+规则模板，跨文件交叉验证                        │
  │   效果：建立"项目参数字典"作为后续检查的基准                 │
  │                                                             │
  │ Step 3: 规则检查（增强）                                     │
  │   当前：关键词存在性搜索                                     │
  │   增强：+数值比对（提取的数值 vs 规范要求值）                │
  │   方法：对262条规则中涉及数值的规则，增加数值提取和比对      │
  │   效果：从"有没有提到"升级为"数值对不对"                     │
  │                                                             │
  │ Step 4: 行业知识注入（新增）                                 │
  │   当前：无                                                  │
  │   新增：将280+条行业检查项转化为规则                         │
  │   分类：                                                     │
  │   ├── 材料规格规则（43条）→ 检查图纸标注的材料规格是否达标   │
  │   ├── 测试验收规则（105条）→ 生成测试验收检查清单           │
  │   ├── 管线综合规则（40条）→ 补充碰撞检测的间距标准          │
  │   └── 建筑类型规则（35条）→ 按建筑类型过滤适用规则          │
  │   效果：从"设计合规"扩展到"施工可验收"                       │
  │                                                             │
  │ Step 5: 报告生成（重构）                                     │
  │   当前：3份Markdown + 1份会审清单                            │
  │   重构：按角色生成不同报告                                   │
  │   ├── 设计审查报告（给设计院）                               │
  │   ├── 施工检查清单（给施工单位）                             │
  │   ├── 验收测试清单（给监理）                                 │
  │   └── 会审决策报告（给甲方）                                 │
  └─────────────────────────────────────────────────────────────┘
```

### 3.4 我们要什么（核心需求）

```
一句话：从"帮审图机构找图纸问题"升级为"帮项目全链条提前发现问题"

具体拆解：

  需求1：更准的检查
    当前：关键词搜索，误报多（搜到"疏散宽度"就判合规）
    目标：数值比对，减少误报（提取疏散宽度数值，与规范值比对）

  需求2：更多的检查维度
    当前：只有设计合规性（262条规则）
    目标：+材料规格 + 测试验收 + 管线间距 + 建筑类型专项

  需求3：更实用的输出
    当前：问题清单（"疏散宽度不足"）
    目标：+检查清单（"用卷尺量走廊宽度，应≥1.4m"）
          +测试方法（"绝缘电阻：500V兆欧表测60秒，应≥0.5MΩ"）

  需求4：更精准的定位
    当前：定位到文件（"建筑-设计说明_unified.json"）
    目标：定位到楼层（"1号楼3层走廊"）

  需求5：面向多角色
    当前：只有审图机构用
    目标：设计院+施工单位+监理+甲方都能用
```

## 六、总结

### 当前系统是什么

> 一个基于DXF文本提取+关键词搜索的图纸合规性检查工具，覆盖262条规则，输出3份Markdown报告。

### 行业需要什么

> 一个基于图纸信息+行业知识的施工全链条问题发现工具，覆盖设计合规+材料规格+测试验收+管线综合，面向设计院/施工单位/监理/甲方多角色输出。

### 差距在哪里

| 维度 | 当前 | 目标 | 差距 |
|------|------|------|------|
| 数据提取 | TEXT/MTEXT | +DIMENSION/ATTRIB/图层 | 提取能力不足 |
| 检查方法 | 关键词搜索 | +数值比对+规则模板 | 检查深度不足 |
| 知识覆盖 | 262条设计规则 | +280条行业规则 | 知识面不足 |
| 输出内容 | 问题清单 | +检查清单+测试方法 | 实用性不足 |
| 使用角色 | 审图机构 | +施工+监理+甲方 | 覆盖面不足 |

### 怎么补

```
P0（本周）：行业知识入库 + bug修复 → 立即增加280条检查能力
P1（1-2周）：增强提取 + 数值比对 + 验收清单 → 提升检查精度
P2（2-4周）：参数锚定 + 材料检查 + 多角色报告 → 扩展使用场景
P3（长期）：BIM支持 + 几何碰撞 + 进度计划 → 架构升级
```

---

*分析基于：实际代码审查 + 6份机电安装专监文档（280+条可检查项）*  
*核心结论：系统需要从"关键词搜索工具"升级为"行业知识驱动的施工全链条问题发现工具"*
