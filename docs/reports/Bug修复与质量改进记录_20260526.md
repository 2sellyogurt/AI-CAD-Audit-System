## 三、P1级修复（严重）

### 3.1 住宅规范误用于公建项目

| 项目 | 内容 |
|------|------|
| 文件 | src/step5_engineering.py, report/report_generator_v50.py |
| 问题 | 报告生成未过滤"不适用"规则，住宅规范（如"卧室净高≥2.4m"）被计入教学楼审查结果 |
| 影响 | 45条不适用规则被误判为问题 |
| 修复 | 5处修改：过滤 `compliance_status == "不适用"` 的规则 |
| 验证 | 回归测试95/95通过，过滤逻辑测试通过 |

### 3.2 Timer死锁问题

| 项目 | 内容 |
|------|------|
| 文件 | engine/performance_monitor.py |
| 问题 | `all_stats()` 持有 `Lock` 后调用 `get_stats()` 也尝试获取同一 `Lock`，导致死锁 |
| 影响 | 性能监控测试卡死 |
| 修复 | 将 `threading.Lock()` 改为 `threading.RLock()`（可重入锁） |
| 验证 | 20项性能监控测试全部通过 |

### 3.3 gc.get_referrers() 性能问题

| 项目 | 内容 |
|------|------|
| 文件 | engine/performance_monitor.py |
| 问题 | `gc.get_referrers()` 在对象多时极慢，导致内存监控卡死 |
| 影响 | 内存监控功能不可用 |
| 修复 | 改用轻量级 `gc.get_count()` + `gc.get_threshold()` |
| 验证 | 内存监控测试正常通过 |

### 3.4 SpatialElement构造参数缺失

| 项目 | 内容 |
|------|------|
| 文件 | engine/object_pool.py |
| 问题 | ObjectPool使用 `SpatialElement()` 无参构造，但该类需要必填参数 |
| 影响 | 对象池无法创建实例 |
| 修复 | 改为工厂函数 `create_element`，提供默认必填参数 |
| 验证 | 9项对象池测试全部通过 |

## 六、经验总结

| 类别 | 经验 |
|------|------|
| 接口一致性 | 新增模块必须核对现有接口的类名、方法名、参数名 |

| 性能陷阱 | gc.get_referrers()等gc操作需谨慎使用 |
| 测试先行 | 每个修复都需配套回归测试验证 |
