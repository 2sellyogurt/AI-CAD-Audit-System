# 基于图纸的模拟施工进度计划生成方案

## 一、第一性原理：为什么要从图纸生成施工进度计划？

### 1.1 核心问题

**问：施工进度计划是怎么编出来的？**

```
传统方式：
├── 施工员看图纸 → 凭经验列工序 → 估算工期 → 编计划
├── 问题1：依赖个人经验，水平参差不齐
├── 问题2：容易漏项（特别是机电交叉）
├── 问题3：图纸问题到施工时才发现，被动调整
└── 结果：计划不准、频繁变更、工期失控

目标方式：
├── 系统读图纸 → 自动识别工序 → 智能排程 → 生成计划
├── 优势1：基于图纸实体，不依赖经验
├── 优势2：自动识别所有工作项
├── 优势3：提前发现图纸问题，主动优化
└── 结果：计划准确、可执行性强
```

### 1.2 本质目标

> **基于图纸信息，自动生成可执行的施工进度计划，并识别图纸问题对施工的影响。**

```
输入：图纸（DXF/Revit）+ 审查结果
  ↓
识别：构件/系统/工程量
  ↓
转化：施工工序 + 工期估算
  ↓
排程：逻辑关系 + 资源平衡
  ↓
输出：施工进度计划（横道图/网络图）+ 风险预警
```

## 二、从图纸到施工计划的转化逻辑

### 2.1 图纸信息 → 施工工序映射

```
图纸内容                    施工工序
─────────────────────────────────────────────────
建筑平面图
├── 墙体、门窗              → 砌筑工程、门窗安装
├── 楼地面                  → 地面垫层、面层施工
├── 楼梯                    → 楼梯结构、栏杆安装
└── 房间功能分区            → 施工段划分

结构施工图
├── 基础（桩/筏板/独立）     → 基础施工工序序列
├── 柱梁板                  → 钢筋→模板→混凝土
├── 楼梯结构                → 楼梯施工
└── 预留预埋                → 预埋件安装

机电施工图
├── 电气桥架/线管           → 电气配管配线
├── 给排水管道              → 管道安装、试压
├── 暖通风管               → 风管制作安装
├── 设备（泵/风机/配电箱）   → 设备安装
└── 末端（灯具/喷头/风口）   → 末端安装

消防施工图
├── 消火栓系统             → 管道安装、栓箱安装
├── 喷淋系统               → 管网安装、喷头安装
├── 报警系统               → 管线敷设、设备安装
└── 防排烟系统             → 风管安装、风机安装
```

```python
class QuantityExtractor:
    """从图纸提取工程量"""
    
    def extract_from_unified_json(self, unified_data):
        """
        从unified.json提取工程量信息
        """
        quantities = {
            '建筑': self._extract_arch_quantities(unified_data),
            '结构': self._extract_struct_quantities(unified_data),
            '电气': self._extract_elec_quantities(unified_data),
            '给排水': self._extract_plumbing_quantities(unified_data),
            '暖通': self._extract_hvac_quantities(unified_data),
            '消防': self._extract_fire_quantities(unified_data)
        }
        return quantities
    
    def _extract_arch_quantities(self, data):
        """提取建筑工程量"""
        # 从文本识别墙体面积、门窗数量、楼地面面积等
        return {
            '墙体面积': self._parse_wall_area(data),
            '门窗数量': self._parse_door_window_count(data),
            '楼地面面积': self._parse_floor_area(data),
            '楼梯数量': self._parse_stair_count(data)
        }
    
    def _extract_elec_quantities(self, data):
        """提取电气工程量"""
        # 识别配电箱数量、桥架长度、灯具数量等
        return {
            '配电箱数量': self._parse_distribution_box(data),
            '桥架长度': self._parse_cable_tray_length(data),
            '灯具数量': self._parse_lighting_count(data),
            '插座数量': self._parse_socket_count(data)
        }
```

#### 模块3：工期估算器（DurationEstimator）

```python
class DurationEstimator:
    """估算工序工期"""
    
    def __init__(self):
        self.productivity_rates = self._load_productivity_rates()
    
    def estimate_duration(self, activity, quantities):
        """
        估算工序工期
        方法：工程量 / 定额产量
        """
        activity_type = activity['type']
        quantity = activity['quantity']
        
        # 获取定额产量（基于企业定额或行业定额）
        productivity = self.productivity_rates.get(activity_type, {})
        
        # 计算工期
        if productivity:
            daily_output = productivity.get('daily_output', 1)
            crew_size = productivity.get('crew_size', 1)
            duration = math.ceil(quantity / (daily_output * crew_size))
        else:
            # 使用经验公式
            duration = self._estimate_by_experience(activity, quantity)
        
        # 考虑审查问题的影响
        duration = self._apply_review_impact(duration, activity)
        
        return duration
    
    def _apply_review_impact(self, duration, activity):
        """
        应用审查问题对工期的影响
        """
        # 如果该活动相关的图纸有严重问题，增加工期
        related_issues = self._get_related_issues(activity)
        
        for issue in related_issues:
            if issue['severity'] == '严重':
                duration *= 1.3  # 增加30%
            elif issue['severity'] == '重要':
                duration *= 1.15  # 增加15%
        
        return duration
```

```python
class Scheduler:
    """施工进度排程"""
    
    def schedule(self, activities, start_date):
        """
        基于CPM算法进行进度排程
        """
        # 建立工序网络
        network = self._build_network(activities)
        
        # 正向计算（最早开始/完成）
        self._forward_pass(network, start_date)
        
        # 反向计算（最晚开始/完成）
        self._backward_pass(network)
        
        # 计算总浮动时间，识别关键路径
        critical_path = self._identify_critical_path(network)
        
        # 资源平衡
        balanced_schedule = self._resource_leveling(network)
        
        return {
            'activities': balanced_schedule,
            'critical_path': critical_path,
            'project_duration': self._calculate_project_duration(network),
            'milestone_dates': self._calculate_milestones(network)
        }
    
    def _identify_critical_path(self, network):
        """识别关键路径"""
        critical_activities = []
        for activity in network:
            if activity['total_float'] == 0:
                critical_activities.append(activity)
        return critical_activities
```

### 3.3 审查结果与进度计划的联动

```python
class ReviewScheduleIntegrator:
    """审查结果与进度计划集成器"""
    
    def integrate(self, schedule, review_results):
        """
        将审查结果集成到进度计划中
        """
        integrated_schedule = schedule.copy()
        
        for activity in integrated_schedule['activities']:
            # 查找与该活动相关的审查问题
            related_issues = self._find_related_issues(
                activity, review_results)
            
            activity['related_issues'] = related_issues
            
            # 如果活动在关键路径上且有严重问题，标记风险
            if activity in integrated_schedule['critical_path']:
                activity['is_critical'] = True
                
                severe_issues = [i for i in related_issues 
                               if i['severity'] == '严重']
                if severe_issues:
                    activity['risk_level'] = '高'
                    activity['risk_description'] = (
                        f"关键路径活动存在{len(severe_issues)}个严重图纸问题")
            
            # 估算问题对工期的影响
            impact = self._estimate_schedule_impact(activity, related_issues)
            activity['schedule_impact'] = impact
        
        return integrated_schedule
    
    def generate_risk_report(self, integrated_schedule):
        """生成进度风险报告"""
        return {
            'critical_path_issues': self._analyze_critical_path_issues(
                integrated_schedule),
            'high_risk_activities': self._identify_high_risk_activities(
                integrated_schedule),
            'schedule_contingency': self._calculate_contingency(
                integrated_schedule),
            'recommended_actions': self._generate_recommendations(
                integrated_schedule)
        }
```

```
输入：施工图纸 + 审查结果
输出：可执行的施工进度计划
价值：
├── 基于图纸实际内容编计划（不依赖经验）
├── 提前识别关键路径上的图纸问题
├── 合理安排资源进场时间
└── 制定风险应对措施
```

### 6.3 图纸会审阶段

```
输入：图纸 + 审查结果
输出：进度计划 + 风险报告
价值：
├── 量化图纸问题对工期的影响
├── 优先解决关键路径上的问题
├── 为整改预留合理时间
└── 形成带时间节点的整改计划
```

## 七、价值总结

### 7.1 核心价值

| 传统方式 | 系统生成方式 |
|---------|-------------|
| 依赖个人经验 | 基于图纸实体 |
| 容易漏项 | 自动识别所有工作项 |
| 图纸问题施工时才发现 | 提前识别并量化影响 |
| 计划与实际偏差大 | 计划可执行性强 |

### 7.2 关键能力

```
图纸 → 工程量 → 工序 → 工期 → 进度计划
         ↑           ↑
    审查结果影响工期估算
    审查结果标注风险
```

### 7.3 实施建议

1. **建立标准工序库**：按专业/系统建立标准工序模板
2. **积累定额数据**：企业定额或参考行业定额
3. **开发工程量识别**：从unified.json提取工程量
4. **开发排程引擎**：基于CPM算法
5. **集成审查结果**：将问题影响量化到工期
