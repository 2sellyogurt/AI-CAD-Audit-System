# AI智能审图系统 v6.0 - 分步工作流操作指南

## 概述

将原 `run_pipeline.py` 的全流程拆分为 **9个独立可执行的步骤脚本**（位于 `src/` 目录），每步聚焦单一任务，降低单轮思考复杂度。

### 分步架构

```
┌──────────────────────────────────────────────────────────────────────────────┐
│                         src/master.py（一键串联）                             │
├──────┬──────┬──────┬──────┬──────┬──────┬──────┬──────┬──────────────────────┤
│Step 0│Step 1│Step 2│Step 3│Step 4│Step 5│Step 6│Step 7│      Step 8          │
│锚点  │DXF   │合规  │错漏  │跨专业│工程  │BIM   │RAG   │  二次审查             │
│提取  │提取  │审查  │排查  │校验  │分析  │管线  │审核  │                      │
│      │      │      │      │      │+报告 │      │      │                      │
└──┬───┴──┬───┴──┬───┴──┬───┴──┬───┴──┬───┴──┬───┴──┬───┴──────────────────────┘
   │      │      │      │      │      │      │      │
   ▼      ▼      ▼      ▼      ▼      ▼      ▼      ▼
 anchor  *_uni  step2  step3  step4  6份报告 step6  step7  step8
 .json   fied   _res   _res   _res   +issues _res   _res   _res
         .json  ult    ult    ult    snapshot ult    ult    ult
                .json  .json  .json          .json  .json  .json
```

### 文件清单

| 文件 | 说明 |
|------|------|
| `src/step0_anchor.py` | 锚点提取，从图纸中提取图号、楼层、轴线范围等位置信息 |
| `src/step1_extract.py` | DXF图纸参数提取，生成JSON汇总文件，支持LLM增强提取 |
| `src/step2_compliance.py` | 合规性审查（280条规则，6大专业+公建专用，四级风险分级，LLM智能判定） |
| `src/step3_defect.py` | 基础错漏排查（标高/净高/碰撞/管综/几何），碰撞按文件分组+收紧阈值 |
| `src/step4_cross_check.py` | 跨专业一致性校验（基础+深度比对） |
| `src/step5_engineering.py` | 工程落地分析 + 6份报告生成 + 问题清单 |
| `src/step6_bim.py` | BIM管线综合分析与碰撞检测 |
| `src/step7_rag.py` | RAG审核，基于检索增强生成的智能审核 |
| `src/step8_review.py` | 二次审查，对前序结果复核，消除误报与遗漏 |
| `src/master.py` | 一键串联执行所有步骤 |
| `src/profession_identifier.py` | 两级策略专业识别，未识别率2.7% |

| `src/llm_client.py` | LLM客户端，智谱glm-4-flash，6个接入点，自动故障转移 |
| `src/performance_monitor.py` | LRU缓存+性能监控 |

**总代码**：128文件，45,842行

## 使用方式

### 方式一：分步执行（推荐）

按顺序逐步执行，每步独立运行，便于检查中间结果和定位问题。

#### Step 0：锚点提取

```bash
python src/step0_anchor.py --dxf-dir /path/to/dxf --output-dir ./json_data
```

**做什么：** 从DXF图纸中提取图号、楼层、轴线范围等位置锚点信息，为后续步骤提供位置定位基础。

**输出：**
- `json_data/anchor_info.json`（含图号、楼层、轴线范围等位置信息）

**Agent 提示词示例：**
> 从这批图纸中提取图号、楼层、轴线范围等位置锚点信息

---

#### Step 1：上传图纸，提取核心参数

```bash
python src/step1_extract.py --dxf-dir /path/to/dxf --output-dir ./json_data
```

**做什么：** 从DXF图纸中提取所有文本实体，自动识别专业（建筑/结构/暖通/给排水/电气/消防）和楼栋，提取标高数据，生成标准化的 `*_unified.json` 文件。支持LLM增强提取，对复杂图纸内容进行语义理解。

**输出：**
- `json_data/建筑-xxx_unified.json`
- `json_data/结构-xxx_unified.json`
- ...（每个DXF文件对应一个JSON）

**专业识别**：采用两级策略，第一级基于文件名关键词匹配，第二级基于图纸内容特征深度识别，未识别率仅2.7%。

**Agent 提示词示例：**
> 提取这5份DXF图纸里的核心参数、标高、专业信息，生成JSON汇总文件

---

#### Step 2：合规性审查

```bash
python src/step2_compliance.py --json-dir ./json_data --output-dir ./output
```

**做什么：** 加载Step 1生成的JSON文件，执行280条规则检查（覆盖6大专业+公建专用规则），联动规范数据库，匹配跨项目经验。支持LLM智能判定，对规则匹配结果进行语义理解和深度校验。结果按四级风险分级（严重/重要/一般/提示）标注。

**输出：**
- `output/step2_compliance_result.json`（含规则检查结果、统计数据、经验匹配结果、LLM判定结果）

**Agent 提示词示例：**
> 对这5份图纸做合规性审查，280条规则逐条检查，输出审查报告

---

#### Step 3：错漏排查

```bash
python src/step3_defect.py --json-dir ./json_data --output-dir ./output
```

**做什么：** 标高计算与净高验算、碰撞检测（按文件分组+收紧阈值，2145虚假→14真实）、管线综合排布分析、几何空间分析（如有DXF）。

**输出：**
- `output/step3_defect_result.json`（含标高、碰撞、管综、几何分析结果）

**Agent 提示词示例：**
> 对这5份图纸做错漏排查，检查标高净高、碰撞、管综排布

---

#### Step 4：跨专业一致性校验

```bash
python src/step4_cross_check.py --json-dir ./json_data --output-dir ./output
```

**做什么：** 跨专业基础比对 + 深度比对（6项新增检查），验证各专业间的一致性。

**输出：**
- `output/step4_cross_check_result.json`（含基础比对、深度比对结果）

**Agent 提示词示例：**
> 对这5份图纸做跨专业校验，检查各专业间的一致性

---

#### Step 5：工程落地分析 + 报告生成

```bash
python src/step5_engineering.py --json-dir ./json_data --output-dir ./output
```

**做什么：** 工程落地全周期分析（施工工艺/成本/运维），生成6份v5.0规范格式报告、图纸会审问题清单、问题快照持久化。报告按四级风险分级（严重/重要/一般/提示）组织。

**输出：**
- `output/强条合规性审查报告.json`
- `output/基础错漏排查报告.json`
- `output/跨专业一致性校验报告.json`
- `output/综合评估摘要.json`
- `output/图纸会审问题清单.json`
- `output/LLM分析报告.json`
- `output/issues_snapshot.json`

**Agent 提示词示例：**
> 基于前面的审查结果，生成完整的6份审查报告和会审问题清单

---

#### Step 6：BIM管线综合

```bash
python src/step6_bim.py --json-dir ./json_data --output-dir ./output
```

**做什么：** 基于BIM模型进行管线综合分析与碰撞检测，检查管线间的空间冲突与排布合理性。

**输出：**
- `output/step6_bim_result.json`（含BIM管线分析、碰撞检测结果）

**Agent 提示词示例：**
> 对BIM模型做管线综合分析，检查管线碰撞与排布合理性

---

#### Step 7：RAG审核

```bash
python src/step7_rag.py --json-dir ./json_data --output-dir ./output
```

**做什么：** 基于检索增强生成（RAG）技术，结合规范知识库对审查结果进行深度校验，调用智谱glm-4-flash模型进行语义理解和规范匹配。

**输出：**
- `output/step7_rag_result.json`（含RAG审核结果、规范匹配详情）

**Agent 提示词示例：**
> 基于规范知识库对审查结果做RAG深度审核

---

#### Step 8：二次审查

```bash
python src/step8_review.py --json-dir ./json_data --output-dir ./output
```

**做什么：** 对前序审查结果进行复核，消除误报与遗漏，确保审查结论的准确性和完整性。

**输出：**
- `output/step8_review_result.json`（含二次审查结果、误报消除、遗漏补充）

**Agent 提示词示例：**
> 对前面的审查结果做二次复核，消除误报和遗漏

### 方式二：一键串联执行

```bash
# 执行全部9步
python src/master.py

# 指定目录
python src/master.py --dxf-dir /path/to/dxf --json-dir ./json_data --output-dir ./output

# 指定建筑类型（公建/住宅）
python src/master.py --dxf-dir ./input --output-dir ./output --building-type 公建

# 跳过Step 1（已有JSON文件时）
python src/master.py --skip-step 1

# 只执行Step 2和Step 3
python src/master.py --only-step 2 3

# 执行到Step 5后停止
python src/master.py --stop-after 5

# 启用LLM增强审查
python src/master.py --dxf-dir ./input --output-dir ./output --enable-llm

# 仅显示执行计划
python src/master.py --dry-run
```

## 数据流向

```
DXF图纸 ──Step0──→ anchor_info.json
      ──Step1──→ *_unified.json ──Step2──→ step2_compliance_result.json
                                            ──Step3──→ step3_defect_result.json
                                            ──Step4──→ step4_cross_check_result.json
                                                              │
                                            ──Step5──────────┘
                                              ↓
                   6份规范报告 + 会审清单 + 问题快照
                                              │
                                            ──Step6──→ step6_bim_result.json
                                            ──Step7──→ step7_rag_result.json
                                            ──Step8──→ step8_review_result.json
```

**关键设计：**
- Step 5 会自动检测 Step 2-4 的中间结果文件。如果存在则直接复用，避免重复计算。
- Step 7（RAG审核）依赖 Step 2 的合规审查结果，结合规范知识库进行深度校验。
- Step 8（二次审查）汇总 Step 0-7 的全部结果进行复核。
- 系统内置 LRU 缓存机制，跨步骤复用计算结果，提升性能。
