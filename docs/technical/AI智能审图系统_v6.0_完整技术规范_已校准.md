## 第一部分：系统愿景与定位

### 1.1 一句话定位

> 帮助监理在图纸会审阶段，通过系统化的审查报告形成对设计单位和施工单位的技术压力。

### 1.2 核心目标

**终极目标**：识别设计→施工→验收→运维全链条中的断裂点

**阶段性目标**：
| 阶段 | 目标 | 使用者 |
|------|------|--------|
| v6.0 | 监理拿着审查报告+施工计划，能在会审会议上有效施压 | 监理 → 设计/施工/业主 |
| v6.1 | 监理能在施工过程中持续跟踪问题整改 | 监理 → 施工方 |
| v6.2 | 监理能通过系统完成验收记录和质量评分 | 监理 → 验收方 |
| v7.0 | 多项目经验积累，形成知识迁移能力 | 全角色 |

### 1.3 核心产物

| 产物 | 作用 | 使用者 |
|------|------|--------|
| **审查报告** | 技术压力的载体，让监理拿着去对设计/施工方施压 | 监理 → 设计/施工/业主 |
| **预测施工计划** | 模拟施工阶段安排，帮助监理提前预判风险点 | 监理 → 施工方/业主 |

### 1.4 系统定位

**不是：** 一个通用的AI审图工具
**而是：** 一个以监理视角为核心、以图纸会审为切入点的技术施压工具

### 2.1 双轨制架构

```
┌─────────────────────────────────────────────────────────────┐
│              AI智能审图系统 v6.0                            │
├──────────────────────┬────────────────────────────────────┤
│   合规硬执行（左轨）   │   经验软提示（右轨）                │
├──────────────────────┼────────────────────────────────────┤
│ • 强制条文检查        │ • 行业经验建议                     │
│ • 数值合规验证        │ • 常见问题提示                     │
│ • 规范引用完整        │ • 施工注意事项                     │
│ • 检查结果：通过/不通过│ • 检查结果：提示/建议              │

│ • 来源：法规条文       │ • 来源：专监文档+实战              │
└──────────────────────┴────────────────────────────────────┘
```

### 2.2 左轨与右轨的核心区别

| 维度 | 合规硬执行（左轨） | 经验软提示（右轨） |
|------|------------------|-------------------|
| 性质 | 确定性（有/没有、对/不对） | 概率性（建议/提示） |
| 依据 | 法律法规、规范条文 | 行业经验、专监文档 |
| 结果 | 必须整改 | 可选采纳 |
| 报告标注 | "违反强条" | "施工建议" |
| 来源 | GB50016、GB50300等 | 6份机电安装专监文档 |

## 第三部分：审图逻辑

### 3.1 分层审查模式

```
┌─────────────────────────────────────────────────────────────┐
│                      第一层：专业独立审查                      │
├─────────┬─────────┬─────────┬─────────┬─────────┬───────────┤
│ 结构工程师│ 建筑工程师│ 电气工程师│ 暖通工程师│ 给排水工程师│ 消防工程师 │
├─────────┴─────────┴─────────┴─────────┴─────────┴───────────┤
│                      第二层：总工综合审查                      │
│              跨专业协调检查 + 冲突检测 + 汇总报告              │
└─────────────────────────────────────────────────────────────┘
```

### 3.2 专业扩展顺序

```
结构 → 建筑 → 电气 → 水暖 → 消防 → 智能化 → 精装
 │      │      │      │      │       │        │
 ▼      ▼      ▼      ▼      ▼       ▼        ▼
v6.0   v6.1   v6.2   v6.3   v6.4    v7.0     v7.1

v6.0先做结构专业，确保结构审查能力完整可用后再扩展。
```

### 3.3 审图粒度

**构件类型全覆盖**：
- 建筑构件：门、窗、墙、楼梯、电梯等
- 结构构件：柱、梁、板、基础、剪力墙等
- 机电构件：管道、桥架、风管、设备、阀门等

**每个构件的审查维度**：
- 合规性：是否符合规范要求
- 可施工性：是否便于施工
- 协调性：是否与其他专业冲突

### 3.4 问题定位：全套定位

```
问题定位信息：
├── 图纸信息
│   ├── 图纸名称
│   ├── 图纸编号
│   └── 专业类型
├── 位置信息
│   ├── 楼层（如：3F）
│   ├── 轴网参考（如：A-1轴附近）
│   └── 坐标（如：X: 12500, Y: 8600）
└── 上下文信息
    ├── 附近文本（如："疏散门 宽1.2m"）
    └── 关联构件（如：相邻的墙、柱）
```

### 3.5 跨专业检查：真实几何碰撞

**碰撞检测流程**：
1. 提取各专业构件的几何信息（包围盒）
2. 建立空间索引（R-tree）
3. 执行碰撞检测
4. 输出碰撞报告（位置、涉及的构件、建议解决方案）

### 3.6 问题处理：去重合并

**去重逻辑**：
- 同一位置 + 同一问题类型 = 重复
- 保留最严重的等级
- 合并多个专业的描述

### 3.7 触发方式：自动触发

**触发条件**：
- 图纸上传后自动开始审查
- 图纸版本更新后自动重新审查（增量）
- 规则库更新后可选择重新审查

## 第四部分：精装审图逻辑

### 4.1 精装定位

精装是最后进场的专业，但审图逻辑上需要：
- 引用前面所有专业的审查结果
- 重点做跨专业协调检查
- 输出独立的精装审查报告

### 4.2 精装审图四层结构

```
┌─────────────────────────────────────────────────────────────┐
│  第一层：精装内部审查（尺寸准确）                              │
│  ├── 家具尺寸 vs 空间尺寸                                     │
│  ├── 洁具尺寸 vs 预留位置                                     │
│  ├── 门窗尺寸 vs 土建洞口                                     │
│  └── 灯具/开关/插座尺寸 vs 安装位置                            │
├─────────────────────────────────────────────────────────────┤
│  第二层：精装-一次机电协调（全套校对）                        │
│  ├── 位置对齐：精装点位与机电管线是否对齐                       │
│  ├── 数量核对：精装图点位数量与机电图是否一致                   │
│  ├── 类型匹配：精装点位类型与机电设计是否匹配                   │
│  └── 标高核对：精装完成面标高与机电安装高度                     │
├─────────────────────────────────────────────────────────────┤
│  第三层：一次机电 vs 二次机电差异分析                          │
│  ├── 喷淋头位置变化 → 是否符合消防验收规范                     │
│  ├── 预留与实际不对位 → 偏差是否可接受                         │
│  ├── 新增管线冲突 → 是否影响原有系统                           │
│  └── 标高冲突 → 是否影响使用功能                               │
│  输出：差异 + 影响 + 建议                                     │
├─────────────────────────────────────────────────────────────┤
│  第四层：精装-管综影响分析（全套分析）                         │
│  ├── 净高验证：机电管线+吊顶后是否满足最小净高                  │
│  ├── 管线排布：根据吊顶标高优化机电管线排布                     │
│  ├── 冲突检测：机电管线与吊顶龙骨、灯具是否冲突                 │
│  └── 优化建议：提供管线调整或吊顶调整建议                       │
└─────────────────────────────────────────────────────────────┘
```

### 4.3 精装审图时机：分阶段审查

```
┌─────────────────────────────────────────────────────────────┐
│  第一阶段：结构+建筑+机电审查（v6.0-v6.4）                   │
│  └── 输出：各专业问题清单 + 跨专业冲突报告                    │
├─────────────────────────────────────────────────────────────┤
│  第二阶段：精装审查（v7.1）                                   │
│  ├── 输入：第一阶段审查结果                                   │
│  ├── 重点：精装-机电协调 + 精装-建筑协调                       │
│  └── 输出：精装审查报告（独立）                                │
└─────────────────────────────────────────────────────────────┘
```

### 4.4 精装问题责任自动判定

| 问题类型 | 判定逻辑 | 责任方 |
|---------|---------|--------|
| 家具尺寸与空间不匹配 | 精装家具尺寸 > 建筑空间尺寸 | 精装设计 |
| 洁具位置与排水管不对齐 | 精装洁具位置 vs 机电排水管位置偏差 > 允许值 | 精装/机电 |
| 开关插座与机电点位偏差 | 精装点位 vs 机电点位距离 > 50mm | 精装设计 |
| 吊顶净高不足 | 机电管线+吊顶厚度 > 层高-梁高 | 机电/精装 |
| 灯具与空调风口冲突 | 精装灯具位置 vs 机电风口位置重叠 | 精装/机电 |

## 第五部分：一次vs二次机电协调

### 5.1 概念定义

```
┌─────────────────────────────────────────────────────────────┐
│  一次机电 = 机电专业设计（原始设计）                          │
│  ├── 消防喷淋系统（喷淋头位置、间距、管径）                   │
│  ├── 空调风管系统（风口位置、风管走向）                       │
│  ├── 给排水系统（洁具接管、排水管位）                         │
│  └── 电气系统（配电箱、回路、管线走向）                       │
├─────────────────────────────────────────────────────────────┤
│  二次机电 = 精装专业设计（精装阶段调整）                       │
│  ├── 灯具位置调整（根据精装布局）                             │
│  ├── 开关插座位置调整（根据家具布置）                         │
│  ├── 空调风口位置调整（根据吊顶造型）                         │
│  └── 洁具位置调整（根据卫生间布局）                           │
├─────────────────────────────────────────────────────────────┤
│  审查基准 = 精装完成面                                        │
│  ├── 吊顶完成面标高                                         │
│  ├── 墙面完成面位置                                         │
│  └── 地面完成面标高                                          │
└─────────────────────────────────────────────────────────────┘
```

### 5.2 审查逻辑

```
一次机电图纸 ──┐
               ├──▶ 提取机电点位/管线 ──▶ 对比 ──▶ 差异分析
二次机电图纸 ──┘         │              │        │
                         │              ▼        ▼
精装完成面 ──────────────┴────▶ 以精装为基准验证
                                 │
                                 ▼
                          ┌─────────────┐
                          │  差异+影响   │
                          │  +建议      │
                          └─────────────┘
```

### 5.3 四类冲突场景

#### 冲突1：喷淋头位置变化

```
审查内容：
├── 新位置是否满足消防规范间距要求
│   ├── 喷淋头间距 ≤ 3.6m（常规）
│   ├── 喷淋头距墙 ≤ 1.8m
│   └── 喷淋头距障碍物 ≥ 0.3m
├── 位置调整后是否需要重新计算消防水量
├── 是否影响其他喷淋头的保护范围
└── 是否被精装造型（吊顶、灯槽）遮挡

输出格式：
├── 差异：原位置(X1,Y1) → 新位置(X2,Y2)，偏移XXmm
├── 影响：间距从3.2m变为4.1m，超出规范要求；需重新计算水量
├── 是否符合消防验收规范：❌ 不符合
└── 建议：建议消防专业重新确认，调整相邻喷淋头位置

严重等级：高（涉及消防验收）
```

#### 冲突2：预留与实际不对位

```
审查内容：
├── 预留洞口位置 vs 精装洁具/设备实际位置
├── 预留管位 vs 精装开关/插座实际位置
└── 偏差是否在允许范围内（通常 ≤ 50mm）

输出格式：
├── 差异：预留管位(X1,Y1) vs 实际安装(X2,Y2)，偏差XXmm
├── 影响：偏差超出允许范围，需现场调整或返工
└── 建议：建议施工前现场复核，必要时调整预留位置

严重等级：中（影响施工进度和成本）
```

#### 冲突3：新增管线冲突

```
审查内容：
├── 新增管线是否与原有管线交叉
├── 交叉点的标高是否冲突
├── 是否有足够的安装和检修空间
└── 新增管线是否影响原有系统的功能

输出格式：
├── 差异：新增管线A与原有管线B在(X,Y)处交叉，标高差仅XXmm
├── 影响：安装空间不足，可能影响检修；原有管线保温层可能受损
└── 建议：建议调整新增管线标高或走向，预留≥200mm检修空间

严重等级：中-高（视冲突程度）
```

#### 冲突4：标高冲突

```
审查内容：
├── 机电点位安装标高 vs 精装完成面标高
├── 吊顶内管线排布后的净高是否满足要求
├── 灯具/风口嵌入深度是否与吊顶厚度匹配
└── 完成面后的使用净高是否满足规范

输出格式：
├── 差异：空调风口底标高2.850m，精装吊顶完成面2.900m，风口被遮挡
├── 影响：风口出风面积减少约30%；会议室制冷效果可能不达标
└── 建议：将风口改为侧出风口型，或将吊顶局部降低

严重等级：中（影响使用功能）
```

## 第六部分：核心数据结构

### 6.1 枚举类型

```python
class DrawingType(str, Enum):
    """图纸类型"""
    ARCHITECTURAL = "建筑"
    STRUCTURAL = "结构"
    ELECTRICAL = "电气"
    HVAC = "暖通"
    PLUMBING = "给排水"
    FIRE = "消防"
    INTELLIGENT = "智能化"
    INTERIOR = "精装"  # 新增
    ELEVATION = "立面图"
    SECTION = "剖面图"
    DETAIL = "详图"
    GENERAL = "总说明"

class Discipline(str, Enum):
    """专业枚举"""
    ARCH = "建筑"
    STRUC = "结构"
    ELEC = "电气"
    HVAC = "暖通"
    PLUMB = "给排水"
    FIRE = "消防"
    SMART = "智能化"
    INTERIOR = "精装"  # 新增
    LANDSCAPE = "景观"

class CheckLevel(int, Enum):
    """审查深度等级"""
    L1_COMPLIANCE = 1       # 合规性审查（强条）
    L2_CONSTRUCTABLE = 2     # 可施工性审查
    L3_TESTABLE = 3         # 可检测性审查
    L4_MAINTAINABLE = 4     # 可维护性审查

class RuleSource(str, Enum):
    """规则来源（双轨制）"""
    MANDATORY = "强制条文"        # 左轨：法规
    INDUSTRY_BEST = "行业经验"    # 右轨：经验

│  ├── 无立面图时：从层高和标准构造推断                        │
│  ├── 无轴网时：从构件分布推断轴网位置                       │
│  ├── 缺少某专业图纸时：标记为"该专业未审查"                  │
│  └── 图纸版本不匹配时：以最新版本为准，记录差异              │
│                                                              │
│  第六层：跨图纸关联修复（融合阶段）                           │
│  ├── 坐标系自动对齐（不同图纸的坐标原点统一）                │
│  ├── 比例尺自动检测与统一                                    │
│  ├── 跨图纸标高一致性校验与修复                              │
│  ├── 跨图纸尺寸一致性校验（同一构件在不同图纸中的尺寸）      │
│  └── 智能补全：综合多图纸信息补全单张图纸的缺失              │
│                                                              │
└─────────────────────────────────────────────────────────────┘

### 12.5 容错置信度体系

```
┌─────────────────────────────────────────────────────────────┐
│                    置信度分级                                 │
├─────────────────────────────────────────────────────────────┤
│                                                              │
│  高置信度（直接提取，无需修复）                               │
│  ├── 图纸中有明确标注                                        │
│  ├── 标注格式规范                                            │
│  ├── 多处信息交叉验证一致                                    │
│  └── 审查结果：正常输出，不降级                              │
│                                                              │
│  中置信度（自动修复，有依据）                                 │
│  ├── 从同类构件推断                                          │
│  ├── 从标准图集引用                                          │
│  ├── 从其他图纸关联获取                                      │
│  └── 审查结果：正常输出，标注"推断值"                        │
│                                                              │
│  低置信度（深度推断，依据不足）                               │
│  ├── 缺失图纸时的推断                                        │
│  ├── 无同类构件参考时的默认值                                │
│  ├── 多处信息不一致时的折中值                                │
│  └── 审查结果：降低严重等级，标注"需人工确认"                │
│                                                              │
└─────────────────────────────────────────────────────────────┘
```

### 12.6 容错与审查结果的关联

```
┌─────────────────────────────────────────────────────────────┐
│                    容错-审查关联规则                          │
├─────────────────────────────────────────────────────────────┤
│                                                              │
│  规则1：修复点不产生新问题                                   │
│  ├── 系统修复的数值不作为审查依据                            │
│  ├── 除非修复置信度=高                                       │
│  └── 避免因修复错误导致误报                                  │
│                                                              │
│  规则2：低置信度降低问题等级                                 │
│  ├── 原本"严重"→ 降为"一般"                                 │
│  ├── 原本"一般"→ 降为"提示"                                 │
│  └── 原本"致命"→ 保持"致命"（安全相关不降级）               │
│                                                              │
│  规则3：修复日志必须可追溯                                   │
│  ├── 每个修复操作记录到修复日志                              │
│  ├── 审查报告中引用修复点时附带修复依据                      │
│  └── 用户可查看原始值和修复值                                │
│                                                              │
│  规则4：容错失败不中断                                       │
│  ├── 修复失败时使用默认值继续                                │
│  ├── 标记为"无法修复"，置信度=低                            │
│  └── 在报告中明确提示该区域审查结果不可靠                    │
│                                                              │
└─────────────────────────────────────────────────────────────┘
