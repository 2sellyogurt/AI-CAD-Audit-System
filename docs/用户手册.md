# 施工图智能审查系统 v6.0 - 用户手册

## 1. 系统简介

施工图智能审查系统 v6.0 是一个自动化施工图审查工具，对 DXF 格式施工图纸执行 **9步工作流** 审查：

1. **锚点提取** - 从图纸中提取图号、楼层、轴线范围等位置锚点信息
2. **DXF图纸参数提取** - 从 DXF 中提取文本、标高、专业信息，支持LLM增强提取
3. **合规性审查** - 280条规则自动匹配检查，覆盖6大专业+公建专用规则，支持LLM智能判定
4. **基础错漏排查** - 标高计算、碰撞检测（按文件分组+收紧阈值）、管线综合
5. **跨专业一致性校验** - 跨专业图纸一致性比对
6. **工程落地分析 + 报告生成** - 工程可行性分析 + 6份规范报告输出
7. **BIM管线综合** - BIM模型管线综合分析与碰撞检测
8. **RAG审核** - 基于检索增强生成的智能审核，结合规范知识库深度校验
9. **二次审查** - 对前序审查结果进行复核，消除误报与遗漏

**核心数据**：
- 规则总数：280条（6大专业 + 公建专用规则）
- 风险分级：四级（严重 / 重要 / 一般 / 提示）
- LLM引擎：智谱 glm-4-flash 默认激活，6个接入点
- 位置信息：图号 + 楼层 + 轴线范围
- 输出报告：6份
- 总代码：128文件，45,842行

## 2. 快速开始

### 2.1 前置条件

- Python 3.11+ 已安装
- ezdxf 库已安装（`pip install ezdxf`）
- DXF 格式施工图纸准备就绪
- 网络连接可用（LLM API调用需要）

### 2.2 一键执行

```bash
# 进入项目目录
cd f:\AI智能审图系统_v6.0_项目开发

# 将DXF图纸放入 input/ 目录，然后执行
python src/master.py --dxf-dir ./input --output-dir ./output

# 指定建筑类型（公建/住宅），自动过滤适用规则
python src/master.py --dxf-dir ./input --output-dir ./output --building-type 公建
```

### 2.3 查看结果

执行完成后，在 `./output/` 目录下查看生成的6份审查报告（Markdown格式）。

## 3. 使用场景

### 场景1：完整审查流程

**需求**：对一批 DXF 图纸进行全面审查，输出全部报告。

**操作**：
```bash
python src/master.py --dxf-dir ./input --json-dir ./json_data --output-dir ./output
```

**流程**：Step 0 → Step 1 → Step 2 → Step 3 → Step 4 → Step 5 → Step 6 → Step 7 → Step 8

**输出**：9个步骤全部执行完毕，生成 6 份报告。

### 场景2：仅审查已有 JSON 数据

**需求**：已有之前提取的 `*_unified.json` 文件，只需执行规则审查和分析。

**操作**：
```bash
python src/master.py --skip-step 1 --json-dir ./json_data --output-dir ./output
```

**输出**：跳过 DXF 提取，从合规审查开始完整执行。

### 场景3：仅执行合规审查

**需求**：只想查看图纸中的强制条文违规情况。

**操作**：
```bash
python src/master.py --only-step 2 --json-dir ./json_data --output-dir ./output
```

**输出**：`step2_compliance_result.json`

### 场景4：分步执行 + 查看中间结果

**需求**：想逐步执行，查看每一步的中间结果后再决定是否继续。

**操作**：
```bash
# Step 0：锚点提取
python src/step0_anchor.py --dxf-dir ./input --output-dir ./json_data

# Step 1：提取 DXF
python src/step1_extract.py --dxf-dir ./input --output-dir ./json_data

# Step 2：合规审查
python src/step2_compliance.py --json-dir ./json_data --output-dir ./output

# Step 3：错漏排查
python src/step3_defect.py --json-dir ./json_data --output-dir ./output

# Step 4：跨专业校验
python src/step4_cross_check.py --json-dir ./json_data --output-dir ./output

# Step 5：工程分析+报告
python src/step5_engineering.py --json-dir ./json_data --output-dir ./output

# Step 6：BIM管线
python src/step6_bim.py --json-dir ./json_data --output-dir ./output

# Step 7：RAG审核
python src/step7_rag.py --json-dir ./json_data --output-dir ./output

# Step 8：二次审查
python src/step8_review.py --json-dir ./json_data --output-dir ./output
```

### 场景5：仅预览执行计划

**需求**：想查看系统会执行哪些步骤、使用哪些参数，但不实际运行。

**操作**：
```bash
python src/master.py --dxf-dir ./input --output-dir ./output --dry-run
```

**输出**：显示执行计划，不执行任何操作。

### 场景6：LLM增强审查

**需求**：利用LLM对规则判定结果进行智能复核，提高审查准确率。

**操作**：
```bash
python src/master.py --dxf-dir ./input --output-dir ./output --enable-llm
```

**说明**：启用LLM后，系统将在合规审查（Step 2）和RAG审核（Step 7）环节调用智谱 glm-4-flash 模型进行智能判定，对规则匹配结果进行语义理解和深度校验。需确保网络连通且API Key已配置。

## 4. 审查内容说明

### 4.1 专业覆盖

| 专业 | 规则数 | 审查重点 |
|------|--------|----------|
| 建筑 | 多条 | 净高、采光、通风、防火分区、疏散宽度等 |
| 结构 | 多条 | 保护层厚度、梁高、板厚、配筋率、抗震等级等 |
| 暖通 | 多条 | 风管尺寸、风口风速、新风量、防排烟、保温层厚度等 |
| 给排水 | 多条 | 管径、坡度、排水距离、消防水量、喷淋覆盖等 |
| 电气 | 多条 | 电缆截面、照明功率密度、防雷等级、配电线路保护等 |
| 消防 | 多条 | 防火间距、疏散距离、消防车道宽度、报警联动等 |
| 公建专用 | 多条 | 公共建筑特有规范要求 |

**总计**：280条规则，6大专业 + 公建专用规则。

### 4.2 风险分级

审查结果采用四级风险分级：

| 等级 | 说明 | 处理建议 |
|------|------|----------|
| **严重** | 违反强制性条文，存在安全隐患 | 必须修改，不得通过 |
| **重要** | 违反重要规范要求，影响使用功能 | 应当修改，需设计回复 |
| **一般** | 不满足一般性规范要求 | 建议修改，可协商 |
| **提示** | 潜在问题或优化建议 | 供参考，酌情处理 |

### 4.3 证据链等级

审查结果附带置信度等级：

- **L3-完整**：有文件 + 证据原文 + 行号 + 规则ID + 规范引用
- **L2-增强**：有文件 + 证据原文 + 行号 + 规则ID
- **L1-基础**：有文件 + 证据原文
- **L0-无证据**：缺少关键证据

### 4.4 建筑类型适配

系统支持根据建筑类型自动过滤适用规则：

- **公建**：启用公共建筑专用规则，过滤住宅专属规则
- **住宅**：启用住宅专属规则，过滤公建专用规则

通过 `--building-type` 参数指定，未指定时默认加载全部规则。

## 5. 输出报告

### 5.1 强条合规性审查报告

- **文件名**: `强条合规性审查报告_*.md`
- **内容**: 280条规则的逐条审查结果，包括合规/不合规/待核实/不适用统计，按四级风险分级标注
- **用途**: 向设计单位反馈强制性条文违规情况

### 5.2 基础错漏排查报告

- **文件名**: `基础错漏排查报告_*.md`
- **内容**: 标高计算、碰撞检测（按文件分组+收紧阈值，2145虚假→14真实）、管线综合排布的分析结果
- **用途**: 发现图纸中的基础错漏问题

### 5.3 跨专业一致性校验报告

- **文件名**: `跨专业一致性校验报告_*.md`
- **内容**: 不同专业图纸之间的标高、轴线、构件位置一致性检查
- **用途**: 发现专业间的图纸冲突

### 5.4 综合评估摘要

- **文件名**: `综合评估摘要_*.md`
- **内容**: 全部审查结果的综合评估与风险概览
- **用途**: 快速了解项目整体审查状况

### 5.5 图纸会审问题清单

- **文件名**: `图纸会审问题清单_*.md`
- **内容**: 按风险等级（严重/重要/一般/提示）和专业分类的问题清单，适用于图纸会审会议
- **用途**: 图纸会审会议直接使用

### 5.6 LLM分析报告

- **文件名**: `LLM分析报告_*.md`
- **内容**: LLM智能判定的详细分析结果，包括语义理解、深度校验、误报消除等
- **用途**: 辅助人工复核，提高审查准确率

## 6. DXF图纸命名规范

为获得最佳审查效果，DXF文件名应包含专业关键词：

| 专业 | 文件名关键词 |
|------|-------------|
| 建筑 | 建筑、平面图、立面、总平面、门窗 |
| 结构 | 结构、梁、柱、板、基础、结施 |
| 暖通 | 暖通、通风、空调、防排烟、HVAC |
| 给排水 | 给排水、给水、排水、消防水、喷淋 |
| 电气 | 电气、强电、弱电、照明、配电 |
| 消防 | 消防、火灾、报警、灭火 |

示例：`建筑-一层平面图.dxf`、`结构-梁配筋图.dxf`

### 6.1 专业识别增强说明

系统采用两级策略进行专业识别：

1. **第一级**：基于文件名关键词匹配，快速分类
2. **第二级**：对第一级未识别的文件，基于图纸内容特征进行深度识别

当前未识别率已降至 **2.7%**，绝大多数图纸可自动归类到正确专业。

## 7. 配置调整

### 7.1 调整性能参数

编辑 `config/project_config.json` 中的 performance 节点：

```json
{
  "performance": {
    "max_file_parse_time": 5,
    "max_rule_check_time": 30,
    "max_report_gen_time": 10,
    "max_memory_usage": 500
  }
}
```

系统内置 LRU 缓存机制与性能监控，自动优化重复计算与内存使用。

### 7.2 调整日志级别

```json
{
  "logging": {
    "level": "DEBUG",
    "file": "./output/logs/system.log"
  }
}
```

### 7.3 LLM配置

系统默认使用智谱 glm-4-flash 模型，配置6个接入点以保障可用性。

**配置方式**：在 `config/project_config.json` 中设置LLM相关参数：

```json
{
  "llm": {
    "provider": "zhipu",
    "model": "glm-4-flash",
    "api_key_env": "ZHIPU_API_KEY",
    "endpoints": [
      "https://open.bigmodel.cn/api/paas/v4/chat/completions"
    ],
    "timeout": 30,
    "max_retries": 3
  }
}
```

**API Key配置**：通过环境变量设置，禁止硬编码：

```bash
# Windows
set ZHIPU_API_KEY=your_api_key_here

# Linux/Mac
export ZHIPU_API_KEY=your_api_key_here
```

**说明**：
- 默认模型：glm-4-flash（快速响应，适合批量审查）
- 接入点数量：6个，自动故障转移
- 启用方式：`--enable-llm` 参数或配置文件中 `llm.enabled: true`

from engine.rule_checker import RuleChecker

loader = JsonLoader("./json_data")

for r in rules:

## 9. 故障排查

| 现象 | 可能原因 | 解决方法 |
|------|----------|----------|
| "未找到任何 .dxf 文件" | DXF目录路径错误 | 检查 `--dxf-dir` 参数路径 |
| "未找到任何 *_unified.json 文件" | 尚未执行Step 1 | 先执行 Step 1 或检查 `--json-dir` |
| DXF提取时报错 | DXF文件版本不兼容 | 确保DXF为 ASCII 或 2010 以上版本 |
| 报告内容为空 | 无输入数据 | 确认DXF文件包含文本内容 |
| 编码错误 | Windows系统编码问题 | 设置 `PYTHONUTF8=1` 环境变量 |
| LLM调用超时 | 网络不通或API Key未配置 | 检查网络连接，确认 `ZHIPU_API_KEY` 环境变量已设置 |
| LLM返回空结果 | API接入点故障 | 系统自动切换备用接入点，6个接入点均失败时检查API Key有效性 |
| LLM费用异常 | 调用量过大 | 检查审查文件数量，glm-4-flash为低成本模型，单次审查费用极低 |
| 专业识别率低 | 文件名缺少关键词 | 参照第6节命名规范，或系统自动启用二级深度识别 |
| 碰撞检测虚假碰撞过多 | 阈值设置过宽 | 系统已默认按文件分组+收紧阈值，2145虚假→14真实 |
