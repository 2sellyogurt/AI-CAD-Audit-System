## 一、项目背景与目标

### 1.1 行业痛点

在建筑工程施工图审查领域，传统人工审查面临以下挑战：

- **审查周期长**：大型项目图纸动辄数千张，人工逐张审查耗时数周
- **规范更新快**：国家规范、地方标准频繁更新，审查人员难以实时掌握
- **跨专业协调难**：建筑、结构、暖通、给排水、电气、消防等多专业交叉，一致性检查复杂
- **经验传承难**：资深审查专家的经验难以标准化、规模化复用
- **问题追溯难**：历史审查问题缺乏系统化管理，同类问题反复出现

### 1.2 项目目标

构建一套**AI驱动的施工图智能审查系统**，实现：

| 目标维度 | 具体目标 |
|---------|---------|
| **效率提升** | 将审查周期从数周缩短至数小时 |
| **规范覆盖** | 内置280条审查规则（6大专业各约40-50条，含23条公建专用规则）+ 规范数据库联动 |
| **专业协同** | 自动检测跨专业不一致问题（基础比对+深度比对） |
| **经验沉淀** | 建立跨项目经验累积机制（ExperienceMatcher） |
| **质量保障** | 证据链四级校验（L0-L3），确保可溯源 |
| **风险分级** | 四级风险分级：严重/重要/一般/提示 |
| **工程分析** | 施工工艺/成本/运维三维度评分 |
| **LLM智能** | 集成智谱glm-4-flash，6个接入点辅助判定与审核 |

## 三、分步工作流设计

### 3.1 为什么拆分？

原 `run_pipeline.py` 是**9步串行**的"黑盒"流程：

```
问题：单轮任务过载
• 输入：DXF图纸
• 处理：9个复杂步骤一次性执行
• 输出：完整报告
• 风险：任一环节出错，整体失败；难以定位问题
```

拆分为**9个独立步骤**后：

```
优势：降低Agent思考复杂度
• 每步聚焦单一任务
• 中间结果可检查、可复用
• 失败可精准定位到具体步骤
• 支持灵活组合（跳过、只执行某步）
```

### 3.2 分步架构

```
┌─────────────────────────────────────────────────────────┐
│                 src/master.py（一键串联）                  │
├──────┬──────┬──────┬──────┬──────┬──────┬──────┬───────┤
│Step 0│Step 1│Step 2│Step 3│Step 4│Step 5│Step 6│Step 7 │Step 8│
│锚点  │DXF   │强条  │错漏  │跨专业│工程  │BIM   │RAG    │二次  │
│提取  │提取  │合规  │排查  │校验  │分析  │管线  │审核   │审查  │
│      │      │审查  │      │      │+报告 │      │       │      │
└──┬───┴──┬───┴──┬───┴──┬───┴──┬───┴──┬───┴──┬───┴──┬────┘
   │      │      │      │      │      │      │      │
   ▼      ▼      ▼      ▼      ▼      ▼      ▼      ▼
 锚点   *_uni  step2  step3  step4  6份报告 BIM   RAG   二次
 数据   fied   _result_result_result+会审   分析  审核   审查
        .json  .json  .json  .json  清单   结果  结果   结果
```

### 3.3 每步详细说明

#### Step 0: 锚点提取

**输入**：DXF文件目录  
**核心文件**：`src/step0_anchor.py`  
**处理**：
- 从DXF图纸中提取关键锚点信息
- 建立图号、楼层、轴线范围的基准定位
- 为后续步骤提供位置信息基础

**输出**：锚点数据文件

---

#### Step 1: DXF图纸参数提取

**输入**：DXF文件目录  
**核心文件**：`src/step1_extract.py`  
**处理**：
- 扫描所有DXF文件
- 提取TEXT/MTEXT文本实体
- 自动识别专业（两级策略：文件名→内容语义，未识别率2.7%）
- 自动识别楼栋（根据project_config.json配置）
- 提取标高数据（正则匹配 + LLM辅助）
- LLM辅助标高提取（智谱glm-4-flash）

**输出**：`{专业}-{文件名}_unified.json`

```json
{
  "raw_texts": ["建筑设计说明", "耐火等级二级", ...],
  "elevations": [{"value": 85.650, "type": "建筑标高"}],
  "metadata": {"discipline": "建筑", "building": "主楼"}
}
```

---

#### Step 2: 强制条文合规性审查

**输入**：`*_unified.json`  
**核心文件**：`src/step2_compliance.py`  
**处理**：
- 加载280条审查规则（6大专业各约40-50条，含23条公建专用规则）
- 建筑类型适配：公建/住宅规则自动过滤
- 对每条规则执行关键词/正则搜索
- 判定合规性（合规/待核实/不合规/不适用）
- 四级风险分级：严重(强条违反)/重要(非强条违规)/一般(待核实)/提示(合规)
- LLM辅助合规判定（智谱glm-4-flash）
- 联动规范数据库补充依据
- 执行经验匹配（跨项目经验）

**输出**：`step2_compliance_result.json`

```json
{
  "rule_results": [...],
  "rule_stats": {"compliant": 0, "need_verify": 0, "non_compliant": 0},
  "experience_results": {...},
  "normative_codes": ["GB 55037-2022", "GB 50016-2014"]
}
```

---

#### Step 3: 基础错漏排查

**输入**：`*_unified.json`  
**核心文件**：`src/step3_defect.py`  
**处理**：
- **标高计算**：梁截面提取、净高验算、梁开洞可行性
- **碰撞检测**：8类文本碰撞（桥架碰撞、次梁阻挡、管线间距等）
- **几何碰撞**：跨专业标高+轴线碰撞（GeometricCollision）
- **轴线定位**：梁管碰撞、管线叠放、柱管冲突
- **几何分析**：DXF几何提取、二维碰撞检测（如有DXF）
- **管综分析**：排布方案可行性、原则合规性、维护空间

**输出**：`step3_defect_result.json`

---

#### Step 4: 跨专业一致性校验

**输入**：`*_unified.json`  
**核心文件**：`src/step4_cross_check.py`  
**处理**：
- **基础比对**：检查各专业间的一致性项
- **深度比对**：6项新增检查（如标高一致性、构件匹配等）

**输出**：`step4_cross_check_result.json`

---

#### Step 5: 工程落地分析 + 报告生成

**输入**：
- `*_unified.json`
- `step2_compliance_result.json`（如存在则复用）
- `step3_defect_result.json`（如存在则复用）
- `step4_cross_check_result.json`（如存在则复用）

**核心文件**：`src/step5_engineering.py`  
**处理**：
- **工程落地分析**：施工工艺适配性、成本合理性、运维便利性
- **施工排程**：construction_schedule.py v2.0
- **LLM辅助工程分析**（智谱glm-4-flash）
- **报告生成**：6份规范格式报告
- **会审清单**：图纸会审问题清单
- **问题持久化**：issues_snapshot.json + 跨次对比

**输出**：
- `强条合规性审查报告.md`
- `基础错漏排查报告.md`
- `跨专业一致性校验报告.md`
- `综合评估摘要报告.md`
- `图纸会审问题清单.md`
- `LLM分析报告.md`
- `issues_snapshot.json`

---

#### Step 6: BIM管线

**输入**：前序步骤中间结果  
**核心文件**：`src/step6_bim.py`  
**处理**：
- BIM管线综合分析
- 管线碰撞检测与优化建议

**输出**：BIM管线分析结果

---

#### Step 7: RAG审核

**输入**：前序步骤中间结果  
**核心文件**：`src/step7_rag.py`  
**处理**：
- 基于检索增强生成的审核
- LLM辅助RAG审核（智谱glm-4-flash）
- 规范条文智能匹配与校验

**输出**：RAG审核结果

---

#### Step 8: 二次审查

**输入**：前序步骤中间结果  
**核心文件**：`src/step8_review.py`  
**处理**：
- 对前序步骤审查结果进行二次校验
- LLM辅助二次审查（智谱glm-4-flash）
- 误报过滤与漏报补充
- 最终审查结论确认

**输出**：二次审查结果

## 五、技术亮点

### 5.1 智能容错机制

**JsonLoader自动修复**：
- 编码检测（UTF-8/GBK/GB2312自动识别）
- 语法修复（去除注释、修复尾逗号、单引号转双引号）
- 结构修复（非dict包装、列表标准化）

### 5.2 证据链四级校验

```
L0-无证据：缺少文件或证据文本 → 标记low_confidence
L1-基础：  有文件+证据 → 可接受
L2-增强：  有文件+证据+行号+规则ID → 可信
L3-完整：  有文件+证据+行号+规则ID+规范依据 → 高可信
```

### 5.3 四级风险分级

```
严重：强条违反 → 必须整改
重要：非强条违规 → 建议整改
一般：待核实 → 需进一步确认
提示：合规 → 符合规范要求
```

### 5.4 LLM智能集成

系统集成智谱 glm-4-flash 大语言模型，6个接入点：
- Step 1：LLM辅助标高提取
- Step 2：LLM辅助合规判定
- Step 5：LLM辅助工程分析
- Step 7：LLM辅助RAG审核
- Step 8：LLM辅助二次审查

### 5.5 跨项目经验累积

系统通过 `engine/experience_matcher.py` 的 ExperienceMatcher 类实现跨项目经验沉淀：

```
Project A ──→ config/experience_context.json ──→ Project B
问题模式      经验知识库                自动匹配相似场景
```

### 5.6 建筑类型自动适配

系统支持公建/住宅规则自动过滤：
- `--building-type residential`：启用住宅相关规则
- `--building-type commercial`：启用公建专用规则（23条）
- 规则配置中 `building_types` 字段控制适用范围

### 5.7 性能优化

- **LRU缓存**（`engine/lru_cache.py`）：对频繁访问的规则配置、规范数据、中间结果进行缓存
- **性能监控**（`engine/performance_monitor.py`）：运行时性能指标采集与报告

### 5.8 专业识别两级策略

```
文件名关键词匹配 → 命中则直接判定
        ↓ 未命中
内容语义分析 → 基于文本内容推断专业
        ↓ 仍未识别
标记为"未识别"（未识别率2.7%）
```

### 5.9 综合评分模型

Step5 工程落地分析提供三维度综合评分：
- **施工工艺评分**：施工难度、工艺成熟度
- **成本评分**：材料成本、施工成本
- **运维评分**：维护便利性、能源效率
