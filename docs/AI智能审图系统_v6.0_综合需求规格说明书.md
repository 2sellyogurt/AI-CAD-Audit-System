# AI智能审图系统 v6.0 — 综合需求规格说明书

**版本**：v6.0  
**日期**：2026-05-20  
**来源**：合并自 docs/reports/ 目录下10份分析报告  
**状态**：已开发完成，持续迭代中

---

## 一、系统定位与核心目标

### 1.1 一句话定义

> **一个能从施工图自动提取信息、按行业规范检查、输出多角色可用成果的AI辅助审查系统。**

### 1.2 解决的核心痛点

| 痛点 | 具体表现 | 本系统解决方案 |
|------|----------|---------------|
| 技术话语权缺失 | 监理在图纸会审中缺乏数据支撑 | 数据驱动的审查报告 + 规范依据 |
| 审查效率低下 | 人工审查一套图纸需3-5天 | 自动化审查，2小时内完成 |
| 专业性受限 | 单人难以掌握全专业知识 | 覆盖建筑/结构/暖通/给排水/电气/消防6大专业 |
| 经验传承困难 | 资深经验难以系统化传承 | 250条规则库 + 经验累积机制 |
| 三维空间盲区 | 传统审查难以发现管线碰撞 | 标高/轴线/碰撞三重检测 |

### 1.3 核心价值量化

| 指标 | 人工审查 | AI辅助审查 | 提升倍数 |
|------|----------|-----------|---------|
| 审查时间 | 3-5天 | ≤2小时 | **10倍+** |
| 问题发现率 | ~30% | ~80% | **2.5倍+** |
| 跨专业覆盖 | 1-2个专业 | 6大专业 | **3-6倍** |
| 规范条文覆盖 | 50-100条 | 250条 | **2.5倍** |

## 二、系统输入

### 2.1 核心输入（必须）

| 输入项 | 格式 | 来源 | 用途 |
|--------|------|------|------|
| 施工图纸 | DXF格式 | 设计院交付 | 全部审查的数据源 |
| 规则库 | JSON格式 | 配置文件 | 合规审查的依据 |
| 项目信息 | JSON格式 | 用户配置 | 项目参数锚定 |

### 2.2 可选输入（增强）

| 输入项 | 格式 | 来源 | 用途 |
|--------|------|------|------|
| LLM API | 环境变量/命令行 | 用户配置 | "待核实"项二次判断 |
| 经验库 | JSON格式 | 历史项目 | 经验匹配与复用 |

### 2.3 输入约束

- **图纸格式**：仅支持DXF格式（AutoCAD标准输出格式）
- **文件命名**：建议格式为`{楼栋}_{专业}.dxf`（如`教学楼_建筑.dxf`）
- **编码**：UTF-8
- **文件大小**：单文件建议≤100MB

## 三、系统输出

### 3.1 核心输出（6份报告）

| 报告 | 受众 | 核心内容 |
|------|------|---------|
| 强条合规报告 | 监理/设计 | 250条规则检查结果，含合规/不合规/待核实分类 |
| 错漏碰缺报告 | 设计/施工 | 图纸错误、遗漏、碰撞、缺陷汇总 |
| 跨专业校验报告 | 全部参建方 | 建筑/结构/机电之间的一致性检查 |
| 施工排程报告 | 施工/监理 | 基于图纸的施工进度计划建议 |
| 会审问题清单 | 全部参建方 | 按施工阶段分组的问题清单，含进度维度分析 |
| BIM空间分析报告 | 设计/施工 | 标高一致性、轴线一致性、碰撞风险分析 |

### 3.2 输出格式

- **主格式**：Markdown（可直接用于报告编写）
- **数据格式**：JSON（结构化数据，便于程序处理）
- **可选格式**：HTML（BIM三维可视化）

### 3.3 输出目录结构

```
output/
├── mandatory_rules_report.md      # 强条合规报告
├── defects_report.md              # 错漏碰缺报告
├── cross_discipline_report.md     # 跨专业校验报告
├── engineering_analysis.md        # 工程落地分析
├── meeting_list.md                # 会审问题清单
├── meeting_list.json              # 会审问题清单(JSON)
├── bim_spatial_report.html        # BIM空间分析报告
├── issues_snapshot.json           # 问题快照(持久化)
└── llm_analysis_report.md         # LLM智能分析报告(可选)
```

## 四、系统架构

### 4.1 六步管线架构

```
Step1(DXF提取) → Step2(合规审查) → Step3(错漏排查) → Step4(跨专业校验) → Step5(报告生成) → Step6(BIM重建)
```

| 步骤 | 脚本 | 职责 | 核心引擎 |
|------|------|------|---------|
| Step1 | step1_extract.py | DXF文本提取、专业/楼栋识别 | dxf_parser, geometry_extractor |
| Step2 | step2_compliance.py | 250条规则合规检查 | rule_checker |
| Step3 | step3_defect.py | 错漏排查、碰撞检测 | collision_detect, elevation_calc |
| Step4 | step4_cross_check.py | 跨专业一致性校验 | cross_discipline |
| Step5 | step5_engineering.py | 报告生成、施工排程 | engineering_analysis, report |
| Step6 | step6_bim.py | BIM三维重建、空间分析 | bim_pipeline, spatial_model |

### 4.2 核心引擎清单（engine/目录）

| 引擎 | 文件 | 职责 |
|------|------|------|
| DXF解析器 | dxf_parser.py | DXF文件解析、文本提取、几何提取 |
| 几何提取器 | geometry_extractor.py | 从DXF提取几何实体（线/圆/弧/块） |
| 几何分析器 | geometry_analyzer.py | 几何关系分析、空间计算 |
| 规则检查器 | rule_checker.py | 250条规则匹配、合规判定 |
| 去重引擎 | dedup_engine.py | 图纸MD5去重、标高/轴线提取 |
| 碰撞检测器 | collision_detect.py | 文本级碰撞检测 |
| 轴线碰撞检测 | axis_collision_detector.py | 基于轴线的碰撞定位 |
| 标高计算 | elevation_calc.py | 标高一致性检查 |
| 管综协调 | mep_coordinator.py | 机电管线综合分析 |
| 跨专业校验 | cross_discipline.py | 跨文件文本比对 |
| 工程分析 | engineering_analysis.py | 施工排程、成本估算、运维分析 |
| BIM管线 | bim_pipeline.py | DXF→空间模型→碰撞检测→3D可视化 |
| 空间模型 | spatial_model.py | 三维空间哈希模型 |
| JSON加载器 | json_loader.py | unified.json批量加载、数据管理 |
| LLM适配层 | llm/ | 通用LLM接口、多供应商支持 |

### 4.3 LLM增强架构

```
engine/llm/
├── __init__.py          # 工厂函数 create_llm()
├── base_adapter.py      # 抽象基类：统一接口、缓存、预算控制
├── openai_adapter.py    # OpenAI兼容适配器(GPT/DeepSeek/通义/智谱)
├── ollama_adapter.py    # 本地Ollama适配器(零成本)
├── trae_adapter.py      # Trae IDE交互式适配器
└── prompt_templates.py  # 5个管线环节的Prompt模板
```

**LLM增强接入点**：

| Step | LLM增强能力 | 触发条件 |
|------|------------|---------|
| Step1 | 标高/轴线语义提取 | 正则提取不足时 |
| Step2 | "待核实"项二次判断 | 规则引擎输出"待核实"时 |
| Step3 | 碰撞风险语义分析 | 文本级碰撞检测后 |
| Step4 | 跨专业一致性分析 | 跨专业比对后 |
| Step5 | 专业报告智能生成 | 报告生成后 |

| 专业 | 规则数 | 覆盖规范 |
|------|--------|---------|
| 建筑 | 50条 | GB50016, GB50352, GB55038 |
| 结构 | 50条 | GB50010, GB50011, GB50009 |

| 电气 | 40条 | GB50054, GB50057, GB50116 |
| 消防 | 40条 | GB50016, GB50084, GB50116 |
| **合计** | **250条** | - |

### 5.2 规则格式

```json
{
  "rule_id": "ARCH-001",
  "name": "疏散走道最小净宽",
  "category": "建筑",
  "description": "疏散走道最小净宽不应小于1.1m",
  "keywords": ["疏散走道", "净宽"],
  "check_type": "any",
  "regex": "",
  "code_reference": "GB50016-2014 第5.5.18条",
  "is_mandatory": true
}
```

### 5.3 四级风险分级

| 等级 | 颜色 | 扣分 | 说明 |
|------|------|------|------|
| 严重 | 红色 | 10分 | 违反强制性条文，必须整改 |
| 重要 | 橙色 | 5分 | 违反推荐性条文，建议整改 |
| 一般 | 黄色 | 2分 | 存在瑕疵，可选整改 |
| 提示 | 蓝色 | 0分 | 仅供参考 |

## 七、跨专业校验能力

### 7.1 基础比对（4项）

| 比对项 | 说明 |
|--------|------|
| 楼层标高一致性 | 建筑/结构/机电标高是否一致 |

| 电气-暖通容量 | 电气容量 vs 暖通设备功率 |
| 给排水-建筑坡度 | 排水坡度 vs 建筑地面标高 |

3. **增量计算**：缓存中间结果，只计算变更部分
4. **图纸去重**：MD5哈希去重，避免重复计算

- **向后兼容**：不传--llm参数时行为完全不变

## 十四、专业审视发现

### 14.1 流程顺序问题

当前工作流是"扁平化"的，所有专业一锅端，没有体现专业间的依赖关系和审查优先级。

**建议**：按"建筑(先导)→结构(承接)→机电(承接)→综合协调→施工落地"的顺序组织审查。

### 14.2 缺少"项目级参数锚定"

实际审图第一步是确认"项目基本参数"（建筑高度、层数、耐火等级等），当前工作流没有独立的"参数锚定"步骤。

**建议**：在Step1之前增加"项目参数提取"步骤，从图纸中自动提取项目基本参数。
