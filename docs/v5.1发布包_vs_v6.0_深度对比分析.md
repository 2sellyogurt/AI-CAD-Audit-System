# 三版本施工图审查系统深度对比：CAD_Audit_Tooln vs v5.1 发布包 vs v6.0

> **生成时间**: 2026-05-19  
> **对比目标**: 梳理三个版本的演进脉络、架构差异、能力边界、技术路线选择  
> **版本 A**: `CAD_Audit_Tooln` (v5.0) — GUI桌面应用 + AI辅助审图  
> **版本 B**: `AI智能审图工作流_v5.1_发布包` — 单文件管线 + 规则引擎  
> **版本 C**: `AI智能审图系统_v6.0` — 模块化企业级系统 + 分步工作流

---

## 一、版本演进脉络

```
CAD_Audit_Tooln (v5.0, 2026-02~03)
    ↓ [提取核心审查逻辑]
```

## 四、数据流与处理管线对比

### 4.1 版本A（Tooln）—— 线性流水线

```
DXF文件 → parse_dxf_file() → 提取文本和实体
                      ↓
          identify_drawing_type() → 确定专业和类型
                      ↓
          ┌───────────┼───────────┐
          ▼           ▼           ▼
  extract_elevations()  extract_professional_data()  evaluate_extraction_quality()
          │           │           │
          └───────────┴───────────┘
                      ↓
             generate_json() → 保存为 *_unified.json
                      ↓
             （可选）call_api() → 调用AI补充分析
                      ↓
             生成最终报告（Markdown/JSON）
```

**特点**: 线性流水线，无中间状态持久化，强依赖AI做智能化增强。

### 4.2 版本B（v5.1）—— 八步编排管线

```
Step 1: C1 质量检测 → A/B/C评级 + 文件元信息
Step 2: 降级检测 → 确定可用特征集(OCR/AI/Geo)
Step 3: M2 文本提取 → MTEXT(0.95) / DIMENSION(0.88) / ATTRIB(0.85)
Step 4: M3 几何建模 → BBOX3D(8种实体) + 轴网正则识别
Step 5: [可选] v5.1后端 → RuleChecker 91条规则并行
Step 6: M4 规则引擎 → expression/lookup_table/ai_judgment 三路执行
Step 7: C4+F4+M6 → 冲突解决 → 错误分类(四级降级) → 置信度标定
Step 8: C3+F5 → 证据链追溯 → JSON/Excel/DXF 输出
```

**核心组件**:
- `PipelineOrchestrator` — 编排器（核心调度逻辑）
- `V51BackendAdapter` — v5.1后端适配器
- TaskQueue + SharedResourceLock — 并发安全
- SHA256哈希 — 配置快照溯源

### 4.3 版本C（v6.0）—— 五步分步解耦管线

```
DXF文件 → step1_extract.py → *_unified.json（持久化）
                      ↓
          ┌───────────┼───────────┐
          ▼           ▼           ▼
  step2_compliance.py  step3_defect.py  step4_cross_check.py
          │           │           │
          ▼           ▼           ▼
  step2_result.json  step3_result.json  step4_result.json
                      │
                      ▼
             step5_engineering.py
                      ↓
          ┌───────────┼───────────┬───────────┐
          ▼           ▼           ▼           ▼
    3份规范报告  会审问题清单  issues_snapshot.json  自定义扩展
```

**核心优势**:
- 分步解耦，中间状态持久化
- 支持部分执行（--skip-step/--only-step/--stop-after）
- 规则驱动确定性输出
- 天然支持CI/CD集成

## 十二、结论与建议

### 12.1 版本选型决策树

```
是否需要GUI界面？
├── 是 → 需要AI辅助判断？
│        ├── 是 → 选 版本A（但需立即安全加固）
│        └── 否 → 选 版本A + 集成v6.0引擎
└── 否 → 需要批量自动化？
         ├── 是 → 选 版本C（企业首选）
         └── 否 → 需要学术研究/证据链？
                  ├── 是 → 选 版本B（v5.1发布包）
                  └── 否 → 快速原型 → 选 版本A
```

### 12.2 终极建议

**最佳实践方案**：

1. **生产环境**（审图机构/大型企业）：
   - 采用 **版本C（v6.0）** 作为核心引擎
   - 搭配 **版本B（v5.1）** 的置信度标定和SHA256溯源
   - 逐步开发GUI前端，参考 **版本A（Tooln）** 的交互设计

2. **研发测试环境**（设计院/研究院）：
   - 采用 **版本B（v5.1）** 进行算法验证
   - 逐步迁移至 **版本C（v6.0）** 获得更好的可维护性

3. **个人使用/快速演示**：
   - 继续使用 **版本A（Tooln）**
   - **立即**将API Key迁移至环境变量注入
   - 后续可考虑升级至融合版本
